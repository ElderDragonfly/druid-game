# Друид — первая комната

Первый прототип браузерной 2D roguelike на TypeScript + Phaser. Название игры ещё не выбрано.

Сейчас есть одна комната, друид, движение с ограничением по стенам, стрельба круглыми снарядами и первый враг — лесной жук. Графика временная и рисуется кодом; изображения и внешние сервисы не нужны.

## Запуск на своём компьютере

Нужны Git, Node.js версии 22.12 или новее и npm. Первый раз скачайте проект:

```bash
git clone https://github.com/ElderDragonfly/druid-game.git
cd druid-game
npm ci
npm run dev
```

Команды запускаются в папке проекта. Откройте в браузере адрес, который напечатает Vite. Для игры нужна клавиатура: WASD — движение, стрелки — стрельба, R — сброс комнаты. Удержание стрелки повторяет выстрелы, один снаряд за выстрел. Можно двигаться и стрелять одновременно. Диагональное движение имеет ту же скорость, что и обычное. При одновременном нажатии нескольких стрелок приоритет: вверх, вниз, влево, вправо.

Облачная среда Codex может запускать и проверять игру, но экран её настройки не предоставляет игровой предпросмотр. Для ручной игры можно скачать/клонировать проект и запустить команды выше локально.

## Получение следующих обновлений

Работаем через ветку `main`: Codex меняет проект в облачной среде, проверяет готовый этап и отправляет коммит на GitHub. Вы получаете изменения в папку на компьютере:

```bash
git pull --ff-only
```

Эту команду запускайте во втором терминале в папке `druid-game`, оставив `npm run dev` работающим в первом. Vite автоматически обновит игру после изменения исходников. Если изменились зависимости (`package.json` или `package-lock.json`), остановите сервер через Ctrl+C, выполните `npm ci` и снова `npm run dev`.

Посмотреть последние коммиты можно командой `git log -3 --oneline`, а изменения на GitHub — на вкладке Commits. После каждого этапа Codex сообщает, что изменилось, как проверено и какой коммит отправлен.

Если `git pull --ff-only` завершился ошибкой, сохраните её текст и пришлите в чат: не удаляйте местные изменения и не используйте принудительный сброс. GitHub хранит код; игру запускаем на своём компьютере. Размещение игры в интернете в этот процесс не входит.

## Как устроен проект

```text
index.html → src/main.ts → Phaser → src/scenes/RoomScene.ts
                                      ↑
                               src/settings.ts

Клавиатура → движение игрока → столкновение со стенами
           → выстрел → движение снаряда → удаление у стены
```

- `src/main.ts` создаёт игру, подключает физику и сцену.
- `src/scenes/RoomScene.ts` рисует комнату и персонажа, читает клавиши, управляет движением и снарядами, выбирает точку появления жука и обрабатывает попадания.
- `src/entities/Beetle.ts` отвечает за преследование, здоровье и отображение жука.
- `src/settings.ts` содержит размеры комнаты, скорости персонажа, снаряда и врага, интервал стрельбы и здоровье врага.
- `src/style.css` оформляет страницу вокруг игры.

Phaser обновляет сцену каждый кадр. Скорости задаются в пикселях в секунду, поэтому движение не привязано к частоте кадров. Снаряды используются повторно вместо бесконечного создания новых объектов.

## Первый враг и его поведение

Один лесной жук появляется в случайной точке внутри комнаты минимум в 240 пикселях от начальной позиции друида. Он движется со скоростью 90 пикселей в секунду, друид — 220. Три попадания уничтожают жука; каждое попадание расходует снаряд. Полоски над жуком показывают оставшееся здоровье, а после победы появляется сообщение. Нажмите R для новой попытки со случайным местом появления.

```text
Позиция друида − позиция жука
             ↓
   Направление к друиду
             ↓
Единичный вектор × скорость жука
             ↓
    Скорость физического тела
```

Жук пересчитывает направление каждый кадр, поэтому следует за новым положением игрока. Нормализация вектора оставляет скорость одинаковой при любой дистанции и направлении. Phaser применяет эту скорость с учётом прошедшего времени. Вблизи друида жук останавливается на расстоянии около 32 пикселей. Контактный урон и здоровье друида пока не добавлены.

В комнате нет внутренних препятствий, поэтому прямого преследования достаточно. Если добавим непроходимые препятствия, понадобится отдельный поиск пути: сначала маршрут вокруг препятствий, затем движение к очередной точке маршрута.

## Проверки

```bash
npm run build
npm test
```

Сборка сначала проверяет типы TypeScript, затем создаёт `dist/`. Команда `npm run preview` запускает собранную версию.

`npm test` самостоятельно запускает временный Vite на порту 4175 и проверяет игру в Chromium: WASD, отпускание клавиш, диагональ, все стены, направления выстрелов, одновременное движение и стрельбу, повторное использование снарядов, сброс и ошибки браузера. Исходные проверки управления изолированы от врага. Отдельный боевой сценарий проверяет случайное безопасное появление, преследование, смену направления, остановку, три настоящих попадания с клавиатуры, исчезновение снарядов и восстановление врага после R. Требуется установленный Chromium. В облачной среде он расположен в `/usr/bin/chromium`; на другом компьютере задайте переменную `CHROMIUM_PATH` с путём к браузеру. Скриншот сохраняется в `test-results/room.png`. Сервер теста завершается автоматически.

## Направление игры

Ориентир — структура The Binding of Isaac: отдельные комнаты, процедурные забеги, враги, боссы, предметы и синергии. Герой — магический друид без превращений в животных. Цветение, сезоны и взаимодействие с растительным окружением — направления для дальнейшего обсуждения; их правила пока не утверждены. Eldruid — личный ник автора, не название игры.

Следующие задачи удобно ставить Codex через желаемое поведение, например: «Добавь одного врага, который медленно идёт к друиду и исчезает после трёх попаданий». Codex меняет проект и проверяет результат; принятые решения сохраняем в документации.
