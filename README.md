# Друид — игровой прототип

Первый прототип браузерной 2D roguelike на TypeScript + Phaser. Название игры ещё не выбрано.

Игра начинается с главного меню у костра. «Играть» открывает выбор персонажа: доступны первая ячейка с друидом и кнопка «Начать», две другие ячейки затемнены. «Выход» пока не выполняет действий. После выбора открывается лесная поляна на всё окно: друид с 3 HP, большой пень посередине, деревья у краёв и кусты внутри. Сейчас это этап работы над окружением: жук и стрельба отключены. Фоны входят в проект; внешние сервисы для игры не нужны. Для друида принят рабочий образ «Лесной странник»: подробный портрет в ячейке выбора и упрощённый спрайт в комнате. Главное меню сохраняет прежнюю иллюстрацию. На экране выбора сидит простая пиксельная версия рабочего друида, связанная с выбранным персонажем. Окружение пока временное, анимация героя ещё не добавлена.

## Запуск на своём компьютере

Нужны Git, Node.js версии 22.12 или новее и npm. Первый раз скачайте проект:

```bash
git clone https://github.com/ElderDragonfly/druid-game.git
cd druid-game
npm ci
npm run dev
```

Команды запускаются в папке проекта. Откройте в браузере адрес, который напечатает Vite. Кнопки меню нажимаются мышью; Enter открывает выбор и запускает выбранного друида. Esc возвращает из комнаты к выбору, затем в главное меню. Для игры нужна клавиатура: WASD — движение, R — новая случайная поляна. Диагональное движение имеет ту же скорость, что и обычное. Друид не проходит сквозь основания деревьев, кусты и пень.

Облачная среда Codex может запускать и проверять игру, но экран её настройки не предоставляет игровой предпросмотр. Для ручной игры можно скачать/клонировать проект и запустить команды выше локально.

## Получение следующих обновлений

Работаем через ветку `main`: Codex меняет проект в облачной среде, проверяет готовый этап и отправляет коммит на GitHub. Вы получаете изменения в папку на компьютере:

```bash
git pull --ff-only
```

Эту команду запускайте во втором терминале в папке `druid-game`, оставив `npm run dev` работающим в первом. Vite автоматически обновит игру после изменения исходников. Если изменились зависимости (`package.json` или `package-lock.json`), остановите сервер через Ctrl+C, выполните `npm ci` и снова `npm run dev`.

Посмотреть последние коммиты можно командой `git log -3 --oneline`, а изменения на GitHub — на вкладке Commits. После каждого этапа Codex сообщает, что изменилось, как проверено и какой коммит отправлен.

Если `git pull --ff-only` завершился ошибкой, сохраните её текст и пришлите в чат: не удаляйте местные изменения и не используйте принудительный сброс. GitHub хранит код; игру запускаем на своём компьютере. Размещение игры в интернете в этот процесс не входит.

## Как устроен проект

```text
index.html → src/main.ts → Phaser
                            ↓
  Boot → MainMenu → CharacterSelect → Room
             ↑          ↑              │
             └── Esc ───┴──── Esc ─────┘

Меню: src/ui + src/data/characters.ts + druidArt + src/assets
Комната: RoomScene → MeadowWorld → meadowTextures
Герой: PNG → druidArt → текстура 32×40 → CHARACTERS.game → RoomScene
Выбор: CHARACTERS.camp → chooseCharacter → фигура на бревне
                         ↑
                 generateMeadow(seed)

Клавиатура → движение друида → физика → препятствия и границы
R → новый seed → новая планировка → безопасный старт
```

- `src/main.ts` создаёт игру и подключает сцены, физику и изменение размера окна.
- `src/scenes/BootScene.ts` загружает фоны и PNG друида, затем подготавливает маленькие текстуры игрового и сидящего друида.
- `src/scenes/MainMenuScene.ts` показывает согласованный фон и кнопки «Играть»/«Выход».
- `src/scenes/CharacterSelectScene.ts` показывает упрощённый лагерь, ячейки с подробным образом и пиксельную фигуру выбранного персонажа на бревне.
- `src/ui/MenuButton.ts` отвечает за внешний вид, наведение и клики кнопок; `src/ui/layout.ts` — за координаты интерфейса и пикселизацию фона; `src/ui/sceneHelpers.ts` — за общие операции и масштаб камеры меню.
- `src/data/characters.ts` задаёт порядок, доступность, подписи, портрет и изображение сидящего персонажа. Пока доступны только данные друида, другие ячейки закрыты.
- `src/rendering/druidArt.ts` задаёт изображения и рамки фигуры, создаёт маленькую игровую текстуру. Арт героя можно менять отдельно от фона, генерации и физики.
- `src/assets/` содержит два фона меню и PNG героя в `characters/`.
- `src/scenes/RoomScene.ts` читает WASD, управляет друидом и камерой, запускает новую поляну и показывает HP.
- `src/world/meadowLayout.ts` генерирует позиции объектов по seed и задаёт размеры препятствий. Не зависит от Phaser: планировку можно проверять отдельно от отрисовки.
- `src/world/MeadowWorld.ts` собирает поляну из планировки, рисует траву и подключает неподвижные физические препятствия.
- `src/rendering/meadowTextures.ts` рисует временные пиксельные текстуры деревьев, кустов, пня и тень героя. Их можно заменить, сохранив правила генерации и движения.
- `src/settings.ts` содержит скорость и здоровье героя, а также параметры прежнего боевого прототипа.
- `src/style.css` размещает игру на всё окно браузера.

Phaser обновляет сцену каждый кадр. Скорости задаются в пикселях в секунду, поэтому движение не привязано к частоте кадров.

## Меню и визуальный стиль

Главное меню снова использует прежнюю согласованную иллюстрацию лесного лагеря с друидом у костра. Детализированный сидящий спрайт поверх фона убран. Экран выбора сохраняет расположение костра и бревна, но использует более простые пиксельные формы. Пиксельная фигура выбранного персонажа на экране выбора и все кнопки рисуются поверх фона отдельно: текст не встроен в изображения. Три ячейки расположены слева; первая доступна, остальные затемнены и не реагируют на выбор. Сидящий образ и подписи обновляются через `chooseCharacter(id)` по данным персонажа. Подробный портрет в ячейке сохраняется независимо от простого рисунка на бревне.

«Лесной лагерь» — заголовок сцены, не утверждённое название игры. Решения об образе героя и дальнейшей модульности записаны в [docs/VISUAL_STYLE.md](docs/VISUAL_STYLE.md). Сценам можно менять оформление независимо от физики и боя комнаты. Каждый новый вход в комнату начинает попытку с полным здоровьем.

Сборка использует относительные пути к ресурсам (`vite.config.ts`), чтобы не привязывать игру к корню веб-сервера. Это подготовка для будущей настольной упаковки; Electron и интеграция со Steam пока не добавлены.

## Лесная поляна

Комната занимает всё окно браузера без рамки и отдельных полос интерфейса. В обычном окне поляна имеет ширину 960 игровых единиц, высота зависит от пропорций окна. В очень широком окне высота остаётся не меньше 405 единиц, а луг расширяется по горизонтали: это сохраняет место для пня, кустов и проходов. Камера показывает её целиком; при изменении размера окна окружение пересобирается с тем же seed, а друид остаётся на безопасной позиции.

В центре расположен большой пень. Деревья случайно размещаются в полосе у краёв, с большей вероятностью ближе к границе. Количество кустов выбирается равновероятно от 4 до 7 включительно, они размещаются во внутренней части поляны. Число деревьев также случайное: базовое значение, соответствующее прежней средней плотности для пропорций окна, ±4. Между основаниями объектов оставлены проходы, место появления друида рядом с пнём свободно. Трава, варианты деревьев и кустов также меняются между попытками. Клавиша R создаёт новую случайную планировку.

Столкновения соответствуют основаниям объектов: стволам и корням деревьев, кустам и пню. Кроны находятся выше земли: можно пройти позади дерева и оказаться закрытым его листвой. Порядок отрисовки зависит от положения на поляне. Границы окна также не выпускают персонажа за пределы комнаты.

Окружение и друид перерисованы под более высокий взгляд сверху: широкие кроны, короткая видимая часть стволов, глубокий срез пня, видимый верх капюшона и плечи. Палитра стала темнее, трава распределяется неоднородными пятнами; формы и детали ориентируются на присланный референс и направление Children of Morta. Это нарисованный 2D-ракурс: числового поворота 3D-камеры нет. Текстуры остаются временными и увеличиваются без сглаживания. Коэффициент `MEADOW_PIXEL_SCALE` находится в `src/world/meadowLayout.ts`. Анимация и дальнейшая детализация окружения ещё предстоят.

### Рабочий образ героя

Выбран первый из [трёх предложенных вариантов](docs/art/druid-sprites-v1/README.md), «Лесной странник». У пояса справа от зрителя сохранены листья, слева цветы заменены связкой отдельных корешков. Капюшон, острая седая борода, тканевый плащ и посох из кривой сосновой ветки с листьями и перьями сохраняют принятый образ.

| Место | Изображение и размер |
| --- | --- |
| Главное меню | Прежняя иллюстрация с друидом у костра |
| Выбор персонажа | Сидящий рисунок 54×75 пикселей, до 22 цветов; отображение 190,8×265 единиц; портрет в ячейке остаётся подробным |
| Игровая комната | Текстура 32×40 пикселей, до 16 цветов; основные формы капюшона, бороды, плаща, сапог и посоха, без мелких украшений |
| Размер героя в комнате | 87,5×109,375 игровых единиц — прежний размер с более подробной сеткой |
| Физическое тело | 20×25 игровых единиц, у ног; не включает выступающий посох и плащ |

Подробный рабочий PNG используется в портрете ячейки выбора. Для бревна и комнаты подготовлены отдельные прозрачные спрайты по одобренным эскизам. Сетка увеличена примерно на треть по каждой стороне: 40×56 → 54×75 для сидящей фигуры и 24×30 → 32×40 для игровой. Сидящий друид значительно крупнее; его масштаб и точка опоры задаются в `CHARACTERS.camp`, независимо от фоновой картинки. Игровая текстура и параметры размера задаются в `CHARACTERS.game`.

При загрузке `druidArt.ts` усредняет тонкие штрихи, создаёт маленькие текстуры, убирает полупрозрачные края и ограничивает палитры. Чуть яснее читаются лицо, борода, руки, складки и посох; мелкие украшения и фактура ткани не возвращаются. Геометрия столкновений задана отдельно от рисунка: игровой размер и физическое тело 20×25 сохраняются, фигура привязана к ногам. Анимации пока нет: ходьба использует один неподвижный кадр.

### Параметры генерации

Правила находятся в `src/world/meadowLayout.ts`, распределение травы и теней — в `src/world/MeadowWorld.ts`.

| Объект / параметр | Значение |
| --- | --- |
| Кусты | От 4 до 7 включительно, каждый вариант равновероятен |
| Деревья при окне 16:9 | База 35, случайное количество от 31 до 39 |
| Деревья при окне 3:2 | База 41, случайное количество от 37 до 45 |
| Другие пропорции | База интерполируется между измеренными значениями прежней комнаты; отклонение всегда от −4 до +4 |
| Пень | 1, в центре |
| Позиции кустов | X: 23–77% ширины, Y: 23–78% высоты; занятые и опасные точки отбрасываются |
| Позиции деревьев | Полоса у краёв; случайное значение в квадрате повышает вероятность расположения ближе к границе |
| Свободный промежуток между основаниями | Не менее 28 игровых единиц |
| Свободное место старта | Область 128×128 вокруг друида, дополнительный отступ от препятствий 16 единиц |
| Варианты деревьев и кустов | 3 рисунка каждого типа |
| Размер пикселя | 2,5 игровые единицы, как у фона выбора персонажа |

Базовая ширина комнаты — 960 игровых единиц; на очень широком окне она увеличивается при минимальной высоте 405. Физический размер пикселя на мониторе зависит от масштаба окна. Для каждого нового входа или R выбирается новый 32-битный seed; он определяет количество и позиции объектов. Один seed и одинаковые размеры комнаты дают одинаковую планировку. Если выбранное количество не поместилось с первой попытки, генератор повторяет размещение с теми же числами, сохраняя диапазоны. Фактическое количество и базовое значение доступны в `scene.layout.counts`.

### Предыдущий боевой прототип

Прежняя комната со стрельбой, преследующим жуком и контактным уроном сохранена в `src/scenes/CombatPrototypeScene.ts`, а жук — в `src/entities/Beetle.ts`. Эта сцена не подключена к игре. В текущей поляне врагов и снарядов нет, HP не расходуются. Поиск пути жука вокруг новых препятствий будет отдельной задачей.

## Проверки

```bash
npm run build
npm test
```

Сборка сначала проверяет типы TypeScript, затем создаёт `dist/`. Команда `npm run preview` запускает собранную версию.

`npm test` самостоятельно запускает временный Vite на порту 4175 и проверяет игру в Chromium. Проверяет меню, закрытые ячейки, выбор и передачу персонажа, прежнее главное меню, пиксельную фигуру на бревне с той же плотностью пикселей, смену изображения через данные персонажа, сохранённый портрет, размер и палитру игровой текстуры, положение физического тела, увеличение пикселей фона, WASD, остановку и диагональ. Проверки поляны охватывают 8000 планировок, безопасный старт, распределение объектов и проходы, настоящие столкновения с каждым типом препятствия с четырёх сторон, границы, R, изменение размера окна и повторные переходы между сценами. Для проверки переключения тест временно предоставляет второму персонажу собственную фигуру, затем возвращает исходные данные и закрытые ячейки. Требуется установленный Chromium. В облачной среде он расположен в `/usr/bin/chromium`; на другом компьютере задайте переменную `CHROMIUM_PATH` с путём к браузеру. Снимки для внутренней проверки сохраняются в `test-results/`. Сервер теста завершается автоматически.

## Направление игры

Ориентир — структура The Binding of Isaac: отдельные комнаты, процедурные забеги, враги, боссы, предметы и синергии. Герой — магический друид без превращений в животных. Цветение, сезоны и взаимодействие с растительным окружением — направления для дальнейшего обсуждения; их правила пока не утверждены. Eldruid — личный ник автора, не название игры.

Следующие задачи удобно ставить Codex через желаемое поведение, например: «Добавь анимацию ходьбы друида, сохранив текущие столкновения с окружением». Codex меняет проект и проверяет результат; принятые решения сохраняем в документации.
