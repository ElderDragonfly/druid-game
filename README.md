# Друид — игровой прототип

Первый прототип браузерной 2D roguelike на TypeScript + Phaser. Название игры ещё не выбрано.

Игра начинается с главного меню у костра. «Играть» открывает выбор персонажа: доступны первая ячейка с друидом и кнопка «Начать», две другие ячейки затемнены. «Выход» пока не выполняет действий. После выбора открывается лесная локация 3840×2160: друид с 3 HP появляется в центре, камера плавно следует за ним, деревья и кусты распределены по всей площади. Сейчас это этап работы над окружением: жук и стрельба отключены. Фоны входят в проект; внешние сервисы для игры не нужны. Для друида принят рабочий образ «Лесной странник»: подробный портрет в ячейке выбора и четыре ракурса выбранного спрайта 64×80 в комнате. Главное меню сохраняет прежнюю иллюстрацию. На экране выбора показан выбранный эскиз с друидом у лагеря, связанный с данными персонажа. Окружение пока временное. При движении во всех четырёх направлениях друид проигрывает четырёхкадровые анимации ходьбы.

## Запуск на своём компьютере

Нужны Git, Node.js версии 22.12 или новее и npm. Первый раз скачайте проект:

```bash
git clone https://github.com/ElderDragonfly/druid-game.git
cd druid-game
npm ci
npm run dev
```

Команды запускаются в папке проекта. Откройте в браузере адрес, который напечатает Vite. Кнопки меню нажимаются мышью; Enter открывает выбор и запускает выбранного друида. Esc возвращает из комнаты к выбору, затем в главное меню. Для игры нужна клавиатура: WASD — движение и поворот: W — спиной, S — лицом к игроку, A — влево, D — вправо; R — новая случайная поляна. После остановки сохраняется последнее направление, при диагональном движении выбирается последняя нажатая активная клавиша. При движении во всех четырёх направлениях работают анимации ходьбы: четыре кадра по 160 мс. После отпускания клавиш или упора в препятствие возвращается стоящий спрайт. Противоположные клавиши взаимно отменяются. Диагональное движение имеет ту же скорость, что и обычное. Друид не проходит сквозь основания деревьев и кусты.

Облачная среда Codex может запускать и проверять игру, но экран её настройки не предоставляет игровой предпросмотр. Для ручной игры можно скачать/клонировать проект и запустить команды выше локально.

## Получение следующих обновлений

Работаем через ветку `main`: Codex меняет проект в облачной среде, проверяет готовый этап и отправляет коммит на GitHub. Вы получаете изменения в папку на компьютере:

```bash
git pull --ff-only
```

Эту команду запускайте во втором терминале в папке `druid-game`, оставив `npm run dev` работающим в первом. Vite автоматически обновит игру после изменения исходников. Если изменились зависимости (`package.json` или `package-lock.json`), остановите сервер через Ctrl+C, выполните `npm ci` и снова `npm run dev`.

Посмотреть последние коммиты можно командой `git log -3 --oneline`, а изменения на GitHub — на вкладке Commits. После каждого этапа Codex сообщает, что изменилось, как проверено и какой коммит отправлен.

Если `git pull --ff-only` завершился ошибкой, сохраните её текст и пришлите в чат: не удаляйте местные изменения и не используйте принудительный сброс. GitHub хранит код; игру запускаем на своём компьютере. Размещение игры в интернете в этот процесс не входит.

## Как устроен проект

```text
index.html → src/main.ts → Phaser
                            ↓
  Boot → MainMenu → CharacterSelect → Room
             ↑          ↑              │
             └── Esc ───┴──── Esc ─────┘

Меню: src/ui + src/data/characters.ts + druidArt + src/assets
Комната: RoomScene → MeadowWorld → meadowTextures
Герой: четыре PNG 64×80 → druidArt → четыре стоящих ракурса → RoomScene
Ходьба: полоса PNG 256×80 → DRUID_WALKS → CHARACTERS.game.walkAnimations → RoomScene
Камера: положение героя → EllipticalFollowCamera → основная камера
HUD: здоровье → отдельная камера экрана, без движения и масштаба
Поворот: WASD → FourWayFacing → направление → CHARACTERS.game.frames
Выбор: CHARACTERS.camp → chooseCharacter → фигура на бревне
                         ↑
                 generateMeadow(seed)

Клавиатура → движение друида → физика → препятствия и границы
R → новый seed → новая планировка → безопасный старт
```

- `src/main.ts` создаёт игру и подключает сцены, физику и изменение размера окна.
- `src/scenes/BootScene.ts` загружает фоны и PNG друида, затем подготавливает маленькие текстуры игрового и сидящего друида.
- `src/scenes/MainMenuScene.ts` показывает согласованный фон и кнопки «Играть»/«Выход».
- `src/scenes/CharacterSelectScene.ts` показывает упрощённый лагерь, ячейки с подробным образом и пиксельную фигуру выбранного персонажа на бревне.
- `src/ui/MenuButton.ts` отвечает за внешний вид, наведение и клики кнопок; `src/ui/layout.ts` — за координаты интерфейса и пикселизацию фона; `src/ui/sceneHelpers.ts` — за общие операции и масштаб камеры меню.
- `src/data/characters.ts` задаёт порядок, доступность, подписи, портрет и изображение сидящего персонажа. Пока доступны только данные друида, другие ячейки закрыты.
- `src/rendering/druidArt.ts` задаёт изображения и рамки фигуры, создаёт маленькую игровую текстуру. Арт героя можно менять отдельно от фона, генерации и физики.
- `src/assets/` содержит два фона меню и PNG героя в `characters/`.
- `src/scenes/RoomScene.ts` читает WASD, управляет друидом и камерой, запускает новую поляну и показывает HP.
- `src/world/meadowLayout.ts` генерирует позиции объектов по seed и задаёт размеры препятствий. Не зависит от Phaser: планировку можно проверять отдельно от отрисовки.
- `src/camera/EllipticalFollowCamera.ts` задаёт овал с полуосями 192×108, плавное следование и ограничения камеры границами мира. Не зависит от Phaser.
- `src/world/MeadowWorld.ts` собирает поляну из планировки, рисует траву и подключает неподвижные физические препятствия.
- `src/rendering/meadowTextures.ts` рисует временные пиксельные текстуры деревьев, кустов, пня и тень героя. Их можно заменить, сохранив правила генерации и движения.
- `src/settings.ts` содержит скорость и здоровье героя, а также параметры прежнего боевого прототипа.
- `src/style.css` размещает игру на всё окно браузера.

Phaser обновляет сцену каждый кадр. Скорости задаются в пикселях в секунду, поэтому движение не привязано к частоте кадров.

## Меню и визуальный стиль

Главное меню снова использует прежнюю согласованную иллюстрацию лесного лагеря с друидом у костра. Детализированный сидящий спрайт поверх фона убран. Экран выбора сохраняет расположение костра и бревна, но использует более простые пиксельные формы. Пиксельная фигура выбранного персонажа на экране выбора и все кнопки рисуются поверх фона отдельно: текст не встроен в изображения. Три ячейки расположены слева; первая доступна, остальные затемнены и не реагируют на выбор. Сидящий образ и подписи обновляются через `chooseCharacter(id)` по данным персонажа. Подробный портрет в ячейке сохраняется независимо от простого рисунка на бревне.

«Лесной лагерь» — заголовок сцены, не утверждённое название игры. Решения об образе героя и дальнейшей модульности записаны в [docs/VISUAL_STYLE.md](docs/VISUAL_STYLE.md). Сценам можно менять оформление независимо от физики и боя комнаты. Каждый новый вход в комнату начинает попытку с полным здоровьем.

Сборка использует относительные пути к ресурсам (`vite.config.ts`), чтобы не привязывать игру к корню веб-сервера. Это подготовка для будущей настольной упаковки; Electron и интеграция со Steam пока не добавлены.

## Лесная поляна

Локация имеет фиксированные размеры **3840×2160 игровых единиц**, независимо от окна браузера. Друид появляется в центре, в точке (1920, 1080). Пня нет. Видимая область при формате 16:9 — 1280×720, примерно девятая часть мира. Высота видимой области составляет 720 единиц; широкий экран показывает больше по горизонтали. При изменении окна меняется только масштаб камеры: seed, позиции препятствий, физическое тело и положение героя сохраняются. Очень широкие окна дополнительно ограничиваются шириной мира, чтобы камера не показывала пространство за его границей.

В центре видимой области находится невидимый **овал 16:9 с полуосями 192 по горизонтали и 108 по вертикали** (полный размер 384×216 игровых единиц). Вертикальная полуось составляет 15% от высоты базовой видимой области. Внутри овала камера стоит. За его границей плавно догоняет друида: время реакции сглаживания 140 мс, не зависит от частоты кадров. После остановки героя камера завершает небольшое догоняющее движение до границы овала и стоит; центрировать персонажа не пытается. Камера ограничена границами мира. WASD и их сочетания дают восемь направлений движения с прежней скоростью 220 единиц/с. HP и подсказка закреплены на экране отдельной камерой и не движутся с миром.

Количество выбирается равновероятно и независимо для каждого забега: **45–63 дерева и 4–7 кустов включительно на всю локацию**. Позиции случайны по всей доступной площади, без уплотнения по краям или ограничения кустов центром. Сохраняются поля у границ, чтобы текстуры не обрезались; между основаниями объектов оставляется зазор 28 единиц. Область появления 128×128 и дополнительный отступ 16 свободны от препятствий. Один seed воспроизводит ту же планировку, R создаёт новую. Диапазоны и параметры находятся в `MEADOW_GENERATION`, размеры мира и параметры камеры — в `MEADOW_WORLD`, оба в `src/world/meadowLayout.ts`.

Столкновения совпадают с основаниями объектов: деревья 50×35, кусты 50×30 игровых единиц. Кроны и верхушки не входят в физическое тело. Отрисовка сортируется по высоте основания: друид может проходить за кронами и перед объектами, сохраняя столкновения с их основанием.

Окружение и друид перерисованы под более высокий взгляд сверху: широкие кроны, короткая видимая часть стволов, глубокий срез пня, видимый верх капюшона и плечи. Палитра стала темнее, трава распределяется неоднородными пятнами; формы и детали ориентируются на присланный референс и направление Children of Morta. Это нарисованный 2D-ракурс: числового поворота 3D-камеры нет. Текстуры остаются временными и увеличиваются без сглаживания. Коэффициент `MEADOW_PIXEL_SCALE` находится в `src/world/meadowLayout.ts`. Дальнейшая детализация окружения ещё предстоит.

### Рабочий образ героя

Выбран первый из [трёх предложенных вариантов](docs/art/druid-sprites-v1/README.md), «Лесной странник». У пояса справа от зрителя сохранены листья, слева цветы заменены связкой отдельных корешков. Капюшон, острая седая борода, тканевый плащ и посох из кривой сосновой ветки с листьями и перьями сохраняют принятый образ.

| Место | Изображение и размер |
| --- | --- |
| Главное меню | Прежняя иллюстрация с друидом у костра |
| Выбор персонажа | Правый лагерь из явно выбранного `character-selection-preview.png`, без перерисовки друида; портрет в ячейке остаётся подробным |
| Игровая комната | Четыре стоящих ракурса 64×80, по четыре кадра ходьбы во всех направлениях 64×80 |
| Размер героя в комнате | 87,5×109,375 игровых единиц — прежний размер с более подробной сеткой |
| Физическое тело | 20×25 игровых единиц, у ног; не включает выступающий посох и плащ |

Подробный рабочий PNG используется в портрете ячейки выбора. Для сидящего друида пользователь явно указал [эскиз экрана выбора](docs/art/druid-detail-preview-v1/character-selection-preview.png). Правый фрагмент этого PNG подключён напрямую: область (840, 80), 696×864 исходных пикселей, отображение 435×540 игровых единиц в точке (525, 50). Рисунок, лицо, поза и детализация не меняются. Интерфейс слева не входит в фрагмент и остаётся интерактивным.

Это иллюстрация друида вместе с окружающим лагерем, а не прозрачный спрайт: самостоятельное отделение фигуры от этого конкретного эскиза ещё не подготовлено. Изображение, масштаб и положение слоя задаются в `CHARACTERS.camp`, поэтому заменять его можно через данные персонажа. Фон под ним, портреты, кнопки и текст остаются самостоятельными элементами.

Игровая текстура, кадры направлений и параметры размера задаются в `CHARACTERS.game`. Принятый [фронтальный спрайт 64×80](docs/art/druid-front-resolution-v1/druid-front-64x80.png) сохранён без изменений. Три остальных ракурса подготовлены из того же одобренного подробного листа тем же способом уменьшения: усреднение мелких штрихов, чёткий прозрачный силуэт, без ограничения палитры. Новая генерация образа не использовалась.

Для каждого направления задан собственный PNG через `DRUID_VIEWS.sourceKey` в `druidArt.ts`. Фигуры имеют одинаковую сетку 64×80, центр опоры x=32 и нижнюю границу ног y=75. Размер кадра на поляне 87,5×109,375 игровых единиц, физическое тело 20×25 сохранены. `FourWayFacing` выбирает направление по клавишам, `RoomScene` меняет кадр. Замена изображения не требует изменений движения и физики. Ноги при повороте остаются на общей опоре, текстуры рисуются без сглаживания. Промежуточных кадров поворота пока нет. Ходьба вниз использует принятый [цикл из четырёх кадров](docs/art/druid-walk-down-v2/walk-down-64x80.png) без изменения рисунка: по 160 мс, полный цикл 640 мс. `DRUID_WALKS` задаёт источник и темп, `CHARACTERS.game.walkAnimations` связывает направления с анимациями. `RoomScene` запускает цикл во время движения и возвращает стоящую позу при остановке. Принятый [цикл вверх](docs/art/druid-walk-other-directions-v1/walk-up-64x80.png) подключён без изменения рисунка с тем же темпом. Последние принятые GIF [ходьбы влево](docs/art/druid-walk-left-v3/README.md) и [вправо](docs/art/druid-walk-right-v1/README.md) подключены на A и D с тем же темпом. PNG 256×80 подготовлены из четырёх кадров каждой GIF: сохранены рисунок и цвета, фон заменён прозрачностью. Слева плащ прикрывает плечо и рукав, посох имеет согласованный коричневый цвет, отдельные пиксели перед ним удалены. Справа свободная рука имеет короткий широкий рукав и небольшой сгиб в локте, её мах сохранён; посох остаётся в дальней левой руке.

### Параметры генерации

Правила находятся в `src/world/meadowLayout.ts`, распределение травы и теней — в `src/world/MeadowWorld.ts`.

| Объект / параметр | Значение |
| --- | --- |
| Кусты | От 4 до 7 включительно, каждый вариант равновероятен |
| Деревья | От 45 до 63 включительно на весь мир, каждый вариант равновероятен |
| Мир | 3840×2160 игровых единиц, независимо от окна |
| Овал камеры | Полуоси 192×108, пропорции 16:9 |
| Пень | Отсутствует |
| Позиции кустов и деревьев | Случайные по всей площади; исключены границы текстур, область старта и занятые точки |
| Свободный промежуток между основаниями | Не менее 28 игровых единиц |
| Свободное место старта | Область 128×128 вокруг друида, дополнительный отступ от препятствий 16 единиц |
| Варианты деревьев и кустов | 3 рисунка каждого типа |
| Размер пикселя | 2,5 игровые единицы, как у фона выбора персонажа |

Физический размер пикселя на мониторе зависит от масштаба камеры. Для каждого нового входа или R выбирается новый 32-битный seed; он определяет количество и позиции объектов. Один seed воспроизводит одинаковую планировку, а изменение окна её сохраняет. Если выбранное количество не поместилось с первой попытки, генератор повторяет размещение с теми же числами. Фактическое количество доступно в `scene.layout.counts`.

### Предыдущий боевой прототип

Прежняя комната со стрельбой, преследующим жуком и контактным уроном сохранена в `src/scenes/CombatPrototypeScene.ts`, а жук — в `src/entities/Beetle.ts`. Эта сцена не подключена к игре. В текущей поляне врагов и снарядов нет, HP не расходуются. Поиск пути жука вокруг новых препятствий будет отдельной задачей.

## Проверки

```bash
npm run build
npm test
```

Сборка сначала проверяет типы TypeScript, затем создаёт `dist/`. Команда `npm run preview` запускает собранную версию.

`npm test` самостоятельно запускает временный Vite на порту 4175 и проверяет игру в Chromium. Проверяет меню, закрытые ячейки, выбор и передачу персонажа, прежнее главное меню, пиксельную фигуру на бревне с той же плотностью пикселей, смену изображения через данные персонажа, сохранённый портрет, размер и палитру игровой текстуры, положение физического тела, увеличение пикселей фона, WASD, остановку и диагональ. Проверки поляны охватывают 8000 планировок, безопасный старт, распределение объектов и проходы, настоящие столкновения с каждым типом препятствия с четырёх сторон, границы, R, изменение размера окна и повторные переходы между сценами. Для проверки переключения тест временно предоставляет второму персонажу собственную фигуру, затем возвращает исходные данные и закрытые ячейки. Требуется установленный Chromium. В облачной среде он расположен в `/usr/bin/chromium`; на другом компьютере задайте переменную `CHROMIUM_PATH` с путём к браузеру. Снимки для внутренней проверки сохраняются в `test-results/`. Сервер теста завершается автоматически.

## Направление игры

Ориентир — структура The Binding of Isaac: отдельные комнаты, процедурные забеги, враги, боссы, предметы и синергии. Герой — магический друид без превращений в животных. Цветение, сезоны и взаимодействие с растительным окружением — направления для дальнейшего обсуждения; их правила пока не утверждены. Eldruid — личный ник автора, не название игры.

Следующие задачи удобно ставить Codex через желаемое поведение, например: «Добавь анимацию ходьбы друида, сохранив текущие столкновения с окружением». Codex меняет проект и проверяет результат; принятые решения сохраняем в документации.
