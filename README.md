# Друид — игровой прототип

Первый прототип браузерной 2D roguelike на TypeScript + Phaser. Название игры ещё не выбрано.

Игра начинается с главного меню у костра. «Играть» открывает выбор персонажа: доступны первая ячейка с друидом и кнопка «Начать», две другие ячейки затемнены. «Выход» пока не выполняет действий. После выбора открывается лесная локация 3840×2160: друид с 3 HP появляется в центре, камера плавно следует за ним, сосны и лиственные деревья распределены вперемешку по всей площади; камни убраны. По миру случайно распределяются 0–9 мирных мышей: пробегают, поднимаются на задние лапки и осматриваются. Жук отключён. Стрелки выпускают в конце каста медленно вращающийся жёлудь во всех восьми направлениях, с одним коротким хаотичным хвостом зелёных листьев; попадание снимает волку 1 HP. Фоны входят в проект; внешние сервисы для игры не нужны. Для друида принят рабочий образ «Лесной странник»: подробный портрет Basic 04 в ячейке выбора и принятые подробные кадры 256×320 во всех восьми направлениях в комнате. Размер героя в мире сохранён. Главное меню сохраняет прежнюю иллюстрацию. На экране выбора сидит Basic 04: обе руки на коленях, посох стоит справа по образцу главного меню. Окружение, фигура и посох — независимые слои, связанные с данными персонажа. В выборе костёр и вода используют [пламя из загруженной GIF](docs/art/selection-camp-uploaded-flame-v1/README.md) и медленное течение воды; шесть светлячков летают по независимым замкнутым траекториям. Окружение пока временное. При движении во всех восьми направлениях друид проигрывает четырёхкадровые анимации ходьбы.

Маленькая доступная карточка «Друид» теперь показывает утверждённый **Druid 04 Basic**: верёвочный пояс и посох без украшений. Сидящая фигура и фон выбора сохранены. В комнате подключены [восемь подробных ракурсов и циклов ходьбы](docs/art/druid-eight-way-v1/README.md), включая четыре диагонали с [ногами, нарисованными вполоборота](docs/art/druid-diagonal-legs-v3/README.md). Для задних диагоналей подключены [попеременные шаги и цельные плечи](docs/art/druid-rear-diagonal-walk-v4/README.md). Для остановок есть отдельные устойчивые позы. Цвет ткани согласован со стоящим лицом к игроку; при ходьбе вверх немного двигаются плечи и складки плаща. Друид идёт со скоростью около 147 единиц/с; темп шагов следует за изменяемой скоростью.

## Запуск на своём компьютере

Нужны Git, Node.js версии 22.12 или новее и npm. Первый раз скачайте проект:

```bash
git clone https://github.com/ElderDragonfly/druid-game.git
cd druid-game
npm ci
npm run dev
```

Команды запускаются в папке проекта. Откройте в браузере адрес, который напечатает Vite. Кнопки меню нажимаются мышью; Enter открывает выбор и запускает выбранного друида. Esc в живом забеге сохраняет его и открывает главное меню; «Продолжить» возвращает к сохранённому состоянию. После гибели Esc по-прежнему открывает выбор персонажа. Для игры нужна клавиатура: WASD — движение и поворот: W — спиной, S — лицом к игроку, A — влево, D — вправо; R — новая случайная поляна. После остановки сохраняется последнее направление, две перпендикулярные клавиши включают соответствующий диагональный ракурс: W+A/W+D/S+A/S+D. При движении во всех восьми направлениях работают анимации ходьбы: четыре кадра примерно по 240 мс при начальной скорости. На задних диагоналях опора и перенос обеих ног занимают равное время. Полный цикл одинаковый — 960 мс. После отпускания клавиш или упора в препятствие возвращается отдельный стоящий спрайт. Повторные короткие нажатия продолжают фазы шага, вместо постоянного повтора первого кадра. Противоположные клавиши взаимно отменяются. Диагональное движение имеет ту же скорость, что и обычное. Друид не проходит сквозь основания деревьев.

Стрелки выполняют жест атаки посохом в восьми направлениях; две соседние стрелки задают диагональ. **Во время каста друид стоит на месте.** Короткое нажатие проигрывает весь жест, удержание повторяет его без движения между повторами. После отпускания заканчивается текущий жест; если WASD всё ещё зажата, ходьба возобновляется. Используется принятый [жест v1 и остальные ракурсы](docs/art/druid-cast-eight-way-v1/README.md), с [постоянными пропорциями вниз и вниз-влево](docs/art/druid-cast-front-stable-v1/README.md), [исправленной рукой в правых направлениях](docs/art/druid-cast-right-v2/README.md) и [исправленным вращением посоха в двух диагоналях](docs/art/druid-cast-diagonal-v2/README.md). При базовой скорострельности `1` жест длится 1005 мс, жёлудь вылетает на 75% анимации — через 753,75 мс. Это в 1,5 раза медленнее прежнего темпа. Изменяемое `actorState.attackRate` одновременно меняет темп анимации и выпуска; значение `2` удваивает скорострельность.

Облачная среда Codex может запускать и проверять игру, но экран её настройки не предоставляет игровой предпросмотр. Для ручной игры можно скачать/клонировать проект и запустить команды выше локально.

В нижней правой комнате новой поляны случайно появляются **3–4 волка**. Остальные комнаты не получают случайных волков; после обнаружения погоня может пересекать условные линии комнат. Начальные позиции не пересекают стволы, других волков и зону обнаружения друида. Волки спокойно бродят, замечают друида в овале с полуосями 426,67×240 и преследуют до конца. Жёлудь, пролетевший через меньший овал 192×108 вокруг волка, также агрит его на друида, даже без попадания. Проверяется весь пройденный отрезок снаряда до ближайшего препятствия. Скорость бега — 0,9 от базовой скорости друида (132 единицы/с); кадры следуют за расстоянием. У каждого волка 2 скрытых HP: первый жёлудь вызывает реакцию на 260 мс, второй запускает готовую смерть (620 мс падения + 1200 мс последний кадр). После полной анимации смерти последний кадр и тень остаются на месте и входят в сохранение забега; новая поляна/R очищает трупы. Трупы не двигаются, не атакуют и не имеют столкновений; новых волков взамен не появляется.

Попадание от атаки волка прерывает ходьбу/каст на 400 мс, снимает 1 HP без отбрасывания. На время реакции повторный урон блокируется, в том числе от нескольких одновременных укусов. Сердечки и счётчик HP обновляются. После третьего попадания мир и управление останавливаются, экран плавно темнеет и показывает красную надпись `You dead`. `R` начинает новую поляну с 3 HP, `Esc` возвращает к выбору персонажа. Реакции нарисованы [для всех восьми направлений](docs/art/druid-hit-eight-way-v1/README.md), включая четыре диагонали; принятые [боковые реакции](docs/art/druid-hit-side-v1/README.md) сохранены. Для проверки повернитесь в нужную сторону и подпустите волка.

## Сценарные комнаты

Мир 3840×2160 разделён **линиями на 3×3 области по 1280×720**. Линии не имеют коллизии, переходы свободные, камера прежняя. Обычный лес (70–99 деревьев) и 0–9 мирных мышей остаются общим окружением.

| Область | Сценарий |
|---|---|
| Центральная | Без сценария: один прежний пень с декоративными грибами |
| Нижняя правая | При старте 3–4 волка, 1–2 бревна, 0–2 собираемых гриба суммарно |
| Нижняя центральная | Осквернённое дерево, которое запускается удержанием E |
| Нижняя левая | Один спящий медведь в случайном свободном месте |
| Остальные пять | Сценарии пока не назначены |

На зелёной лужайке осквернённого дерева удерживайте **E одну секунду**. Работает общий индикатор справа у головы, на время удержания запрещены остальные действия. Коллизия только у проекции ствола **28×22**, зелёная площадка проходима и служит отдельной зоной взаимодействия.

Появляются **три мухи** из новой пользовательской GIF: 2 HP, скорость 0,8 (117,33 ед./с), урон 1. Они вылетают из кроны по видимой дуге в разные стороны. Точки приземления выбираются в овале 960×540 (70–100% полуосей 480×270), внутри комнаты, с проверкой препятствий. Дополнительная высота дуги — до 160 единиц. До приземления их нельзя ранить: желуди пролетают под ними; физические столкновения с окружением и врагами при этом остаются. После приземления начинается волнообразная погоня: синусоидальная составляющая амплитудой до 54 единиц, длина волны 300, пауза на каждой вершине/впадине **500 мс**. Возле препятствий волна временно уступает полноценному маршруту с поворотами; при касании ствола муха сначала выходит из контакта и затем облетает его. Соседних живых врагов она также старается обходить, сохраняя физические коллизии. На свободном месте волна возобновляется, рядом с друидом приоритет получает атака.

У мухи только левый/правый вид: вправо отражаются те же исходные кадры. Вверх/вниз не дорисовываются. Полёт, атака и смерть взяты из GIF; крылья продолжают двигаться при зависании. Жало наносит урон на 300-й мс атаки продолжительностью 800 мс. Первое попадание желудя прерывает жало и даёт реакцию на 260 мс: наклон и короткое затухающее отбрасывание до 18 единиц по направлению снаряда. Физика останавливает отбрасывание у стволов, брёвен и других врагов. Мигания, цветовой вспышки и изменения прозрачности при попадании нет. Затем муха выравнивается и продолжает погоню с новым маршрутом. Второе попадание запускает исходную смерть на 1100 мс, включая частицы и исчезновение. После смерти всех трёх дерево зеленеет **в восемь состояний за 1,4 с**, без деформации картинки. Повторного запуска нет. **Награда ещё не определена и не выдаётся**; событие `tree-cleansed` испускается после полного позеленения. Разлёт, фаза волны, зависание, реакция на попадание и прогресс роста сохраняются через Escape/«Продолжить».

Рядом с деревом резервируется место без обычных крон; брёвна размещаются до обычных деревьев, чтобы их количество всегда соответствовало сценарию. Состояние очищения, индивидуальные HP/фазы и погибшие враги сохраняются через Esc → «Продолжить». Старые сохранения загружаются с прежней раскладкой; для новых сценариев начните новый забег или нажмите **R**.

Живые враги сталкиваются друг с другом, включая волка с насекомым; трупы остаются проходимыми. Общий пул `physics/EnemyCollisions.ts` принимает и начальных врагов, и появляющихся при очищении. Мыши в него не входят. Зелёная подстилка ритуального дерева отделена от ствола без изменения исходных пикселей: друид рисуется поверх травы, ствол и крона сохраняют обычную сортировку по глубине.

Модули: `data/roomScenarios.ts` — диапазоны и назначение комнат; `world/rooms.ts` — геометрия и план; `CleansingEncounter` — волна и её сохранение; `CleansingTree` — состояния дерева; `ForestInsect` — бой и визуализация; `behavior/InsectFlight` — разлёт из кроны, волнообразная погоня и зависания. Базовые характеристики нового врага находятся отдельно от волка в `src/data/entities.json`, раздел `forestInsect`. Овалы обнаружения и маршрутизация используют общий с волком профиль; время атаки мухи берётся из её GIF. [Подготовка дерева](docs/art/cleansing-tree-v1/README.md) · [Кадры насекомого](docs/art/forest-fly-v2/README.md).

## Спящий медведь

В нижней левой комнате новой поляны появляется **ровно один медведь**. Место выбирается по seed случайно внутри комнаты, с запасом от границ, стволов и крон и с проверкой доступного пути. Остальные комнаты не получают медведей. После пробуждения он может преследовать друида по всей локации, линии комнат не являются стенами.

Пробуждение происходит при приближении друида в овал с полуосями **96×54** — вдвое меньше овала движения камеры. Визуальный подъём занимает 800 мс и составлен из уже подготовленных поз; затем начальный период ходьбы **2 секунды**, после которого включается бег. Близко к друиду он может атаковать уже во время начального периода. Попадание желудя также будит спящего медведя; пролёт мимо сам по себе его не будит.

Базовые характеристики: **5 HP**, ходьба **0,6 = 88 ед./с**, бег **0,8 = 117⅓ ед./с**, урон каждой атаки **1 HP**. При каждом замахе с равной вероятностью выбирается удар одной лапой, укус или удар двумя передними лапами. Урон проверяется один раз в момент контакта соответствующего рисунка и только если друид всё ещё рядом. На время замаха медведь останавливается. Темп ходьбы/бега следует фактическому расстоянию; при упоре в препятствие лапы не бегут на месте.

Спящий и живой медведь имеют столкновения с друидом, всеми врагами, стволами и брёвнами. Ширина/высота тела **96×28** учитываются в маршруте и локальном обходе соседей; выход из касания препятствия использует тот же исправленный подход, что у мух. После исчерпания HP он остаётся без коллизии и не возрождается. **Отдельной анимации смерти пока нет**: временно используется затемнённая лежачая поза. Награда/лут не добавлены.

Сон, пробуждение, начальная ходьба, текущая случайная атака, её таймер, повреждения и победа сохраняются через Esc → «Продолжить». Старые сохранения с прежней пустой нижней левой комнатой продолжаются без добавления медведя; для третьего сценария нажмите **R в игре** или начните новый забег.

Данные медведя — раздел `bear` в `src/data/entities.json`, карточка «Медведь» доступна в редакторе. В ней меняются HP, обе скорости, урон и начальное время ходьбы; изменения применяются к живому медведю. Рисунок и все анимации имеют обе стороны, правые версии отражены точно без перекрашивания. [Игровые кадры и опоры](docs/art/bear-game-v1/README.md).

## Пень и начало обряда

На каждой новой локации появляется **один пень** в случайном месте стартового экрана. Смещение от старта — в пределах ±360 по горизонтали и ±160 по вертикали, не ближе 150 единиц к точке появления. Под него резервируется свободная от деревьев/крон площадка **260×240** единиц; брёвна также не перекрывают подход. Пень блокирует движение и желуди, учитывается в маршрутах животных.

Подойдите на расстояние до **44 единиц от коллизии пня**: **справа у головы друида** появится толстое круглое кольцо с E. **Удерживайте E примерно 1 секунду** — кольцо заполнится против часовой стрелки. Сам пень не меняет ни рисунок, ни цвет: свечение и круг на земле удалены. Индикатор следует за друидом; у основания пня больше нет отдельной подсказки или полосы прогресса. Пока E удерживается, все действия персонажа заблокированы: движение, каст и будущие способности. Начатый каст отменяется. Отпускание E, отход, попадание или потеря фокуса сбрасывают неполное удержание. Повторной активации нет. Готовое состояние сохраняется при Esc → «Продолжить», новая поляна R создаёт неактивный пень. Старые сохранения без пня загружаются; чтобы увидеть его, начните новый забег или нажмите R.

Общий модуль `src/interaction/HoldInteraction.ts` отвечает за длительное взаимодействие: время по умолчанию `DEFAULT_HOLD_DURATION_MS = 1000`, для другой цели можно задать `holdDurationMs` и действие `completeInteraction()`. `src/ui/HoldInteractionIndicator.ts` рисует общий индикатор; `StumpRitual` отвечает только за пень и результат его активации. Единая проверка `Druid.canStartAction` закрыта на время E; новые способности и предметы должны проверять её перед запуском. Входящий урон и реакция на удар продолжают работать. Сбор грибов остаётся обычным коротким нажатием E.

Это пока только взаимодействие без визуального изменения пня. Враги сохраняют прежнее поведение. Событие `stump-activated` оставлено для будущего отдельного сценария проклятия/очищения леса. [Исходник и подготовка изображения](docs/art/ritual-stump-v1/README.md).

## Брёвна с грибами

В нижней правой комнате случайно распределяются **1–2 серых бревна** из отдельного рисунка. Тестовых четырёх брёвен вокруг старта больше нет. Каждое получает случайное отклонение **−15°…+15°** от исходного ракурса, без зеркального отражения. Большие углы старых сохранений при продолжении ограничиваются этим диапазоном; места брёвен и оставшиеся грибы сохраняются. Деревьев по-прежнему **70–99**. Всего на комнату выбираются **0–2 гриба**, затем случайно распределяются по её брёвнам. На одном бревне грибы одного вида из двух принятых вариантов. Крепления поворачиваются вместе с древесиной, сами грибы остаются вертикальными.

**E — взаимодействовать с ближайшим бревном, на котором остались грибы.** Достаточно подойти с любой стороны: до 44 игровых единиц от центра тела до древесины. Расстояние до самих грибов не учитывается; касаться бревна необязательно. Одно нажатие убирает один гриб; удержание не повторяет сбор. Каждый собранный гриб восстанавливает **1 HP**, до максимума. При полном здоровье гриб не собирается и остаётся на бревне. Счётчика и инвентаря пока нет. Сбор сохраняется при Esc → «Продолжить».

Брёвна уменьшены примерно на треть, без серой тени; исходная сетка — 2 игровые единицы на пиксель. Поворот общий для рисунка, коллизии, маршрутов животных и точек сбора грибов. Коричневые варианты исключены из генерации. При продолжении старого забега сохраняется его раскладка; для новой случайной локации после обновления нажмите **R**.

[Исходники и правила подготовки](docs/art/fallen-logs-v2/README.md). Нижняя серая строка с управлением убрана; клавиши работают как прежде и описаны выше.

## Редактор существ

`npm run editor` запускает локальный сервер и открывает редактор друида, волка, мыши, лесного насекомого и медведя в браузере. Если уже запущен `npm run dev`, откройте `/editor.html` по тому же адресу. В редакторе доступны реальные игровые анимации, характеристики и параметры поведения. «Сохранить в проект» пишет `src/data/entities.json` и обновляет открытый забег; для изменения количества мышей нужна новая поляна (R). Число волков и врагов очищения нового мира задают сценарии; поля общей популяции волков оставлены для прежней генерации. Новых зависимостей нет.

[Подробная инструкция: запуск, изменение, сохранение, единицы измерения и GitHub](docs/entity-editor.md). Значения ниже описывают исходный баланс; после сохранения в редакторе игра использует ваши числа. Лут пока не реализован.

## Музыка и сохранение

В главном меню и выборе персонажа звучит [одобренная тема лесного лагеря](docs/audio/forest-camp-v1/README.md). Это один зацикленный трек: переход между меню и настройками не перезапускает его. В игре он приостановлен, при возвращении в меню продолжается. Кнопка «Настройки» в главном меню открывает отдельный экран: динамик включает/выключает музыку, полоска с перетаскиваемым ползунком задаёт громкость 0–100% и показывает процент. Щелчок по полоске также выбирает уровень. «Назад» или Esc возвращают в главное меню. В главном меню и выборе персонажа звуковых элементов в углу больше нет. Обе настройки сохраняются; выключение музыки не сбрасывает громкость. Начальное значение 80% сохраняет прежнюю громкость. При первом открытии браузер может разрешить звук только после первого клика или клавиши.

**Esc, пока друид жив**, записывает один слот в браузере и открывает главное меню. Появляется **«Продолжить»**. Запоминаются HP/изменяемые характеристики, позиция и ракурс друида, камера, точное расположение деревьев, состояния/HP оставшихся волков, трупы, мыши, фазы каста/попадания/атак и летящие желуди. Забег не идёт, пока открыто меню; продолжение работает и после перезагрузки страницы. Сохранение локально для того же браузера и адреса игры, без серверов или аккаунта. Декоративный хвост листьев не сохраняется, маршруты обхода деревьев пересчитываются.

«Играть» открывает выбор для нового забега; сам старый слот очищается только после «Начать». `R` начинает новую поляну и также очищает слот. Смерть удаляет сохранение: погибший забег нельзя продолжить. Повреждённые/несовместимые данные не показывают кнопку. Если браузер не разрешает запись, продолжение работает в открытой вкладке и меню сообщает об этом.

Модули: `audio/MenuMusic.ts` — общий трек и настройка, `ui/MusicToggle.ts` — кнопка, `persistence/snapshots.ts` — формат состояния, `persistence/runSave.ts` — проверка/хранилище. Персонажи и снаряды сами создают/восстанавливают свои снимки; `RoomScene` связывает их с меню.

## Получение следующих обновлений

Работаем через ветку `main`: Codex меняет проект в облачной среде, проверяет готовый этап и отправляет коммит на GitHub. Вы получаете изменения в папку на компьютере:

```bash
git pull --ff-only
```

Эту команду запускайте во втором терминале в папке `druid-game`, оставив `npm run dev` работающим в первом. Vite автоматически обновит игру после изменения исходников. Если изменились зависимости (`package.json` или `package-lock.json`), остановите сервер через Ctrl+C, выполните `npm ci` и снова `npm run dev`.

Посмотреть последние коммиты можно командой `git log -3 --oneline`, а изменения на GitHub — на вкладке Commits. После каждого этапа Codex сообщает, что изменилось, как проверено и какой коммит отправлен.

Если `git pull --ff-only` завершился ошибкой, сохраните её текст и пришлите в чат: не удаляйте местные изменения и не используйте принудительный сброс. GitHub хранит код; игру запускаем на своём компьютере. Размещение игры в интернете в этот процесс не входит.

[Полная инструкция: как самостоятельно сделать коммит и отправить настройки на GitHub](docs/git-workflow.md).

## Как устроен проект

```text
index.html → src/main.ts → Phaser
                            ↓
  Boot → MainMenu → CharacterSelect → Room
             ↑          ↑              │
             └── Esc ───┴──── Esc ─────┘

Меню: src/ui + src/data/characters.ts + druidArt + src/assets
Комната: RoomScene → MeadowWorld → environment
Арт окружения: PNG-атлас → forestArt → кадры деревьев
Земля: тёмная подстилка + seed → forestFloor → единая текстура мира
Герой: CHARACTERS → Druid { definition, actorState, behavior } ← RoomScene
Ходьба: PNG (все восемь направлений 256×320) → druidArt → Druid
        общий кадр 256×320; скорость → темп анимации
Волк: data/wolf → Wolf { definition, actorState, behavior }
       WolfBehavior → WolfNavigation → движение/атака → wolfArt + исходная тень
Мыши: seed → mousePopulation → Mouse { definition, actorState, behavior }
       GIF + новые фазы → mouseArt; MouseWander → случайная цель
Камера: положение героя → EllipticalFollowCamera → основная камера
HUD: здоровье → отдельная камера экрана, без движения и масштаба
Поворот: WASD → EightWayFacing → направление → CHARACTERS.game.frames
Выбор: CHARACTERS.camp → chooseCharacter → фигура на бревне + отдельные props
       selectionCampArt → постоянное окружение с пустым бревном
                         ↑
                 generateMeadow(seed)

Клавиатура → движение друида → физика → препятствия и границы
R → новый seed → новая планировка → безопасный старт
```

- `src/main.ts` создаёт игру и подключает сцены, физику и изменение размера окна.
- `src/scenes/BootScene.ts` загружает фоны и PNG друида, затем подготавливает маленькие текстуры игрового и сидящего друида.
- `src/scenes/MainMenuScene.ts` показывает согласованный фон и кнопки «Играть»/«Выход».
- `src/scenes/CharacterSelectScene.ts` показывает упрощённый лагерь, ячейки с подробным образом и пиксельную фигуру выбранного персонажа на бревне.
- `src/ui/MenuButton.ts` отвечает за внешний вид, наведение и клики кнопок; `src/ui/layout.ts` — за координаты интерфейса и пикселизацию фона; `src/ui/sceneHelpers.ts` — за общие операции и масштаб камеры меню.
- `src/data/characters.ts` задаёт порядок, доступность, подписи, портрет и изображение сидящего персонажа. Пока доступны только данные друида, другие ячейки закрыты.
- `src/rendering/druidArt.ts` задаёт изображения и рамки фигуры, создаёт маленькую игровую текстуру. Арт героя можно менять отдельно от фона, генерации и физики.
- `src/assets/` содержит два фона меню и PNG героя в `characters/`.
- `src/scenes/RoomScene.ts` читает WASD, управляет друидом и камерой, запускает новую поляну и показывает HP.
- `src/world/meadowLayout.ts` генерирует позиции объектов по seed и задаёт размеры препятствий. Не зависит от Phaser: планировку можно проверять отдельно от отрисовки.
- `src/camera/EllipticalFollowCamera.ts` задаёт овал с полуосями 192×108, плавное следование и ограничения камеры границами мира. Не зависит от Phaser.
- `src/world/MeadowWorld.ts` собирает поляну из планировки, рисует фон земли и подключает неподвижные физические препятствия.
- `src/entities/Mouse.ts` связывает мышь с физикой и анимациями; `src/behavior/MouseWander.ts` задаёт мирный цикл без ссылки на друида; `src/data/mouse.ts` хранит размеры, скорость и диапазоны пробежек.
- `src/world/forestFloor.ts` собирает подстилку из случайных фрагментов по seed и подбирает неровные стыки. Алгоритм не зависит от Phaser.
- `src/rendering/forestFloor.ts` читает принятую картинку и переносит готовую подстилку в игровую текстуру с фильтром NEAREST.
- `src/world/grassCoverage.ts` задаёт маски пучков и глубину перекрытия ступней; `src/rendering/GrassForeground.ts` рисует передние травинки из тех же пикселей поля.
- `src/data/environment.ts` связывает активную сосну и четыре архивных дерева с изображениями, масштабом, точками опоры и физическими основаниями; активный пул задаётся отдельно.
- `src/rendering/forestArt.ts` загружает выбранные PNG-атласы и добавляет кадры без изменения рисунка. Тень героя сохранена отдельным PNG. Старые деревья и кусты удалены.
- `src/entities/Druid.ts` связывает общее описание персонажа, собственное `actorState` (HP, скорость, направление) и `DruidMovement`. Базовые HP и скорость — в `CHARACTERS.stats`; изменения `player.actorState.speed` меняют движение и темп без изменения типа. Мыши имеют ту же структуру ссылок: общий `MOUSE`, отдельные состояние и `MouseWander`.
- `src/world/mousePopulation.ts` выбирает численность и свободные позиции мышей для всей локации.
- `src/settings.ts` хранит параметры отключённого боевого прототипа.
- `src/style.css` размещает игру на всё окно браузера.

Phaser обновляет сцену каждый кадр. Скорости задаются в пикселях в секунду, поэтому движение не привязано к частоте кадров.

## Меню и визуальный стиль

Главное меню снова использует прежнюю согласованную иллюстрацию лесного лагеря с друидом у костра. Детализированный сидящий спрайт поверх фона убран. Экран выбора сохраняет расположение костра и бревна, но использует более простые пиксельные формы. Пиксельная фигура выбранного персонажа на экране выбора и все кнопки рисуются поверх фона отдельно: текст не встроен в изображения. Три ячейки расположены слева; первая доступна, остальные затемнены и не реагируют на выбор. Сидящий образ и подписи обновляются через `chooseCharacter(id)` по данным персонажа. Подробный портрет в ячейке сохраняется независимо от сидящей фигуры. Текущая [сидящая версия Basic 04](docs/art/druid-basic-seated-v1/README.md) и стоящий справа посох отделены от окружения; `camp.props` позволяет заменять экипировку при выборе персонажа.

«Лесной лагерь» — заголовок сцены, не утверждённое название игры. Решения об образе героя и дальнейшей модульности записаны в [docs/VISUAL_STYLE.md](docs/VISUAL_STYLE.md). Сценам можно менять оформление независимо от физики и боя комнаты. Каждый новый вход в комнату начинает попытку с полным здоровьем.

Сборка использует относительные пути к ресурсам (`vite.config.ts`), чтобы не привязывать игру к корню веб-сервера. Это подготовка для будущей настольной упаковки; Electron и интеграция со Steam пока не добавлены.

## Лесная поляна

Локация имеет фиксированные размеры **3840×2160 игровых единиц**, независимо от окна браузера. Друид появляется в центре, в точке (1920, 1080). Пня нет. Видимая область при формате 16:9 — 1280×720, примерно девятая часть мира. Высота видимой области составляет 720 единиц; широкий экран показывает больше по горизонтали. При изменении окна меняется только масштаб камеры: seed, позиции препятствий, физическое тело и положение героя сохраняются. Очень широкие окна дополнительно ограничиваются шириной мира, чтобы камера не показывала пространство за его границей.

В центре видимой области находится невидимый **овал 16:9 с полуосями 192 по горизонтали и 108 по вертикали** (полный размер 384×216 игровых единиц). Вертикальная полуось составляет 15% от высоты базовой видимой области. Внутри овала камера стоит. За его границей плавно догоняет друида: время реакции сглаживания 140 мс, не зависит от частоты кадров. После остановки героя камера завершает небольшое догоняющее движение до границы овала и стоит; центрировать персонажа не пытается. Камера ограничена границами мира. WASD и их сочетания дают восемь направлений движения со стартовой скоростью 220 × 2/3 ≈ 146,67 единиц/с. HP и подсказка закреплены на экране отдельной камерой и не движутся с миром.

На локации генерируется **70–99 деревьев включительно** (примерно на 25% больше прежних 56–79). Для каждого дерева независимо выбирается с равной вероятностью один из двух видов: [одобренная тёмно-зелёная сосна](docs/art/pine-preview-v1/README.md) или [новое лиственное дерево](docs/art/broadleaf-tree-v1/README.md). Предыдущие четыре дерева сохранены в каталоге и PNG, но исключены из случайной генерации. Активные ID задаются в `TREE_SPAWN_POOL` в `src/data/environment.ts`. Позиции случайны по всей площади без уплотнения по краям. Камни и отдельные кусты удалены; пеньки и лежащие деревья не включены. Сохраняются поля у границ, чтобы текстуры не обрезались; между основаниями объектов оставляется зазор 28 единиц. Область появления 128×128 и дополнительный отступ 16 свободны от физических препятствий; изображения также не перекрывают эту область. Один seed воспроизводит ту же планировку и подстилку, R создаёт новые. Диапазоны и параметры находятся в `MEADOW_GENERATION`, размеры мира и параметры камеры — в `MEADOW_WORLD`, оба в `src/world/meadowLayout.ts`.

Столкновения совпадают с основаниями объектов. У активной сосны основание 32×18 игровых единиц. Кроны и верхушки не входят в физическое тело. Отрисовка сортируется по высоте основания: друид может проходить за кронами и перед объектами, сохраняя столкновения с их основанием.

Друид сохраняет согласованный рисунок и ракурс; окружение остаётся двумерным. Одобренный PNG сосны подключён напрямую: масштаб 0,15625 даёт примерно 146×263 игровых единицы, фильтр NEAREST. Размеры и точка опоры сосны находятся в `src/assets/environment/pine.json`; нового дерева — в `docs/art/broadleaf-tree-v1/sprite.json`. Лиственное дерево вырезано из загруженного JPEG без перекрашивания, масштаб 0,375 даёт 165×267,75 игровых единиц. Коллизия ограничена основанием ствола 36×4, крона проходима. [Архив прежних деревьев](docs/art/conifer-trees-v1/README.md) сохранён отдельно. Земля использует [второй эскиз травы с видимой высотой](docs/art/upright-grass-preview-v1/README.md): приглушённую лесную зелень, с травинками, направленными вверх по экрану. Одобренный PNG загружается напрямую, его рабочая копия 256×256 уменьшается с фильтром NEAREST. Из неё собирается поле 3072×1728 из 1032 случайных фрагментов. Повороты и отражения отключены, чтобы сохранять ракурс и освещение. Для каждого стыка выбирается лучший из 12 кандидатов, затем проводится неровная линия по наиболее похожим пикселям. Цвета копируются напрямую, без размытия. Тени у оснований деревьев рисуются поверх. Итоговая текстура масштабируется до мира с фильтром NEAREST; размер её пикселя задаётся отдельно через `FOREST_FLOOR.pixelScale` в `src/world/forestFloor.ts` и составляет 1,25 игровой единицы — вдвое мельче первого варианта. Оба эскиза и все предыдущие источники сохранены. Статичная трава слегка перекрывает низ обуви друида: около 5 игровых единиц. Передние травинки копируются из тех же пикселей поля, с учётом положения их основания; рисунок подстилки и образ героя не меняются. Отдельная пиксельная маска исключает грунт и просветы между травинками: на ровном покрове обувь видна полностью. Покачивание и приминание пока не добавлены.

Сумки, растения и подвески оставлены для будущего снаряжения.

| Главное меню | Прежняя иллюстрация с друидом у костра |
| Выбор персонажа | Правый лагерь из явно выбранного `character-selection-preview.png`, без перерисовки друида; портрет в ячейке остаётся подробным |
| Игровая комната | Принятые фронт/спина и ходьба вниз/вверх 256×320; боковые направления пока прежние 64×80, на общей сетке ×4 без сглаживания |
| Размер героя в комнате | 87,5×109,375 игровых единиц — прежний размер с более подробной сеткой |
| Физическое тело | 20×25 игровых единиц, у ног; не включает выступающий посох и плащ |

Подробный рабочий PNG используется в портрете ячейки выбора. Для сидящего друида пользователь явно указал [эскиз экрана выбора](docs/art/druid-detail-preview-v1/character-selection-preview.png). Правый фрагмент этого PNG подключён напрямую: область (840, 80), 696×864 исходных пикселей, отображение 435×540 игровых единиц в точке (525, 50). Рисунок, лицо, поза и детализация не меняются. Интерфейс слева не входит в фрагмент и остаётся интерактивным.

Это иллюстрация друида вместе с окружающим лагерем, а не прозрачный спрайт: самостоятельное отделение фигуры от этого конкретного эскиза ещё не подготовлено. Изображение, масштаб и положение слоя задаются в `CHARACTERS.camp`, поэтому заменять его можно через данные персонажа. Фон под ним, портреты, кнопки и текст остаются самостоятельными элементами.

Игровой образ — **Basic 04**: верёвочный пояс, сапоги без шнуровки, голая кривая ветка-посох. Четыре полосы ходьбы и неподвижные позы находятся в [druid-basic-walk-v1](docs/art/druid-basic-walk-v1/README.md). Вверх/вниз сохранены принятые позы, изменены только принадлежности и палитра; боковые циклы используют спокойный короткий шаг и опору на посох. Вправо свободная согнутая рука проходит немного вперёд корпуса, дубликат кисти убран, горизонтальный размах ног сокращён на 25%. Влево ненадолго видна только кисть дальней руки из-за края одежды.

Сетка кадра 64×80, центр опоры x=32, ноги на y=75. Размер кадра в мире 87,5×109,375, физическое тело 20×25. PNG копируются без изменения цветов с NEAREST; прежняя дополнительная перекраска боковых сапог больше не применяется. Старые варианты сохранены в архивных папках.

`DRUID_WALKS` задаёт четыре кадра по 160 мс при опорной скорости 220. `Druid` применяет `anims.timeScale = скорость / 220`: при начальных 146,67 единиц/с кадр длится 240 мс, цикл — 960 мс. Изменение скорости во время движения сохраняет текущий шаг. Диагональ нормализована; при скольжении вдоль стены темп учитывает только свободную составляющую движения. При остановке, нулевой скорости, потере фокуса или упоре в препятствие возвращается неподвижная поза того же Basic. `FourWayFacing` по-прежнему определяет ракурс по WASD.

### Предыдущий боевой прототип

Прежняя комната со стрельбой, преследующим жуком и контактным уроном сохранена в `src/scenes/CombatPrototypeScene.ts`, а жук — в `src/entities/Beetle.ts`. Эта сцена не подключена к игре. На текущей поляне появляются мирные мыши: `бег → подъём → осматривание → опускание → новый бег`. Они размещаются по всему миру без привязки к старту; пробежки 60–130 единиц со скоростью 90 единиц/с. Осматривание длится 5,4 с, подъём и опускание — по 0,36 с. Новая цель выбирается независимо от друида, с проверкой пути и столкновениями с деревьями. При отсутствии пути мышь осматривается на месте. Контакт с друидом не блокирует его и не наносит урон. Спрайты и подробности подготовки описаны в [mouse-v1](docs/art/mouse-v1/README.md). В актуальной поляне работают желуди и урон от укусов волков. Поиск пути жука вокруг новых препятствий будет отдельной задачей.

## Проверки

```bash
npm run build
npm test
```

Сборка сначала проверяет типы TypeScript, затем создаёт `dist/`. Команда `npm run preview` запускает собранную версию.

`npm test` самостоятельно запускает временный Vite на порту 4175 и проверяет игру в Chromium. Проверяет меню, закрытые ячейки, выбор и передачу персонажа, прежнее главное меню, пиксельную фигуру на бревне с той же плотностью пикселей, смену изображения через данные персонажа, сохранённый портрет, размер и палитру игровой текстуры, положение физического тела, увеличение пикселей фона, WASD, остановку и диагональ. Проверки поляны охватывают 200 планировок с активной сосной, пустой пул и 2000 планировок при явном включении архивных деревьев: безопасный старт, распределение объектов и настоящие столкновения с четырёх сторон. Архив используется только в тестовых сценах; в игре появляются только одобренные сосны. Также проверяются подстилка по seed, границы мира, R, изменение размера окна и повторные переходы между сценами. Для проверки переключения тест временно предоставляет второму персонажу собственную фигуру, затем возвращает исходные данные и закрытые ячейки. Требуется установленный Chromium. В облачной среде он расположен в `/usr/bin/chromium`; на другом компьютере задайте переменную `CHROMIUM_PATH` с путём к браузеру. Снимки для внутренней проверки сохраняются в `test-results/`. Сервер теста завершается автоматически.

## Направление игры

Ориентир — структура The Binding of Isaac: отдельные комнаты, процедурные забеги, враги, боссы, предметы и синергии. Герой — магический друид без превращений в животных. Цветение, сезоны и взаимодействие с растительным окружением — направления для дальнейшего обсуждения; их правила пока не утверждены. Eldruid — личный ник автора, не название игры.

Следующие задачи удобно ставить Codex через желаемое поведение, например: «Добавь анимацию ходьбы друида, сохранив текущие столкновения с окружением». Codex меняет проект и проверяет результат; принятые решения сохраняем в документации.

Проверка контакта с волком: для столкновения и попадания учитывается край плаща — +10 единиц слева и +6 справа от прежнего тела. Граница взаимодействия 36×25; верх/низ и проходы между деревьями сохраняют прежние размеры. Физическое тело друида для мира остаётся 20×25; параметры находятся в `CHARACTERS[0].game.wolfContactPadding`.

Атака желудем во всех восьми направлениях: выпуск у границы контакта друида на 75% жеста (753,75 мс из 1005 мс) при скорострельности `1`, скорость 1,5 = 220 единиц/с, вращение 90°/с. Один короткий хвост: листья появляются по одному через случайные 8–19 единиц, хаотично дрейфуют и исчезают за 430–730 мс. При попадании в чужой физический объект жёлудь исчезает; волк получает 1 урон. Уже выпущенные листья продолжают двигаться и затухать после столкновения. Попадание волка до выпуска отменяет снаряд. [Подробные параметры и устройство](docs/art/acorn-projectile-v1/README.md).

У друида есть изменяемая характеристика `range` со стартовым значением **1**; она также показана в карточке выбора. Дальность 1 — овал с пределом 512 единиц по горизонтали и 216 по вертикали (30% условного экрана 1280×720), от точки выпуска. Диагональная дальность вычисляется по этому же овалу. Последние 55 единиц пути (250 мс при скорости 220) жёлудь ускоренно снижается по дуге с высоты 38 до земли и исчезает точно на пределе, без дополнительного пролёта. До приземления столкновения и урон работают; после него остаются только декоративные листья. Модификатор дальности применяется при создании снаряда и не меняет уже летящий жёлудь.

Главное меню и выбор персонажа занимают всё окно, как игровая сцена: слои лагеря заполняют экран с сохранением пропорций, а кнопки и текст масштабируются отдельно и остаются видимыми при изменении размеров. На узких окнах кадр смещается в сторону друида и посоха. Исходные фон, сидящий персонаж, посох, огонь, вода и светлячки остаются отдельными слоями; новые PNG не создавались.

Отдельная проверка границ эффектов лагеря в WebGL: `npm run test:camp-render`. Она запускает временный Vite на 4183 и Chromium с программным WebGL, проверяет три размера окна, прозрачные края огня/воды и сохранение анимации. Как и для `npm test`, можно задать путь к Chromium через `CHROMIUM_PATH`.
