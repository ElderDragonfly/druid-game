# Друид — игровой прототип

Первый прототип браузерной 2D roguelike на TypeScript + Phaser. Название игры ещё не выбрано.

Игра начинается с главного меню у костра. «Играть» открывает выбор персонажа: доступны первая ячейка с друидом и кнопка «Начать», две другие ячейки затемнены. «Выход» пока не выполняет действий. После выбора открывается комната с друидом, 3 HP, стрельбой и лесным жуком с контактной атакой. Фоны входят в проект; внешние сервисы для игры не нужны. Игровые спрайты и персонаж на экране выбора пока временные.

## Запуск на своём компьютере

Нужны Git, Node.js версии 22.12 или новее и npm. Первый раз скачайте проект:

```bash
git clone https://github.com/ElderDragonfly/druid-game.git
cd druid-game
npm ci
npm run dev
```

Команды запускаются в папке проекта. Откройте в браузере адрес, который напечатает Vite. Кнопки меню нажимаются мышью; Enter открывает выбор и запускает выбранного друида. Esc возвращает из комнаты к выбору, затем в главное меню. Для игры нужна клавиатура: WASD — движение, стрелки — стрельба, R — сброс комнаты. Удержание стрелки повторяет выстрелы, один снаряд за выстрел. Можно двигаться и стрелять одновременно. Диагональное движение имеет ту же скорость, что и обычное. При одновременном нажатии нескольких стрелок приоритет: вверх, вниз, влево, вправо.

Облачная среда Codex может запускать и проверять игру, но экран её настройки не предоставляет игровой предпросмотр. Для ручной игры можно скачать/клонировать проект и запустить команды выше локально.

## Получение следующих обновлений

Работаем через ветку `main`: Codex меняет проект в облачной среде, проверяет готовый этап и отправляет коммит на GitHub. Вы получаете изменения в папку на компьютере:

```bash
git pull --ff-only
```

Эту команду запускайте во втором терминале в папке `druid-game`, оставив `npm run dev` работающим в первом. Vite автоматически обновит игру после изменения исходников. Если изменились зависимости (`package.json` или `package-lock.json`), остановите сервер через Ctrl+C, выполните `npm ci` и снова `npm run dev`.

Посмотреть последние коммиты можно командой `git log -3 --oneline`, а изменения на GitHub — на вкладке Commits. После каждого этапа Codex сообщает, что изменилось, как проверено и какой коммит отправлен.

Если `git pull --ff-only` завершился ошибкой, сохраните её текст и пришлите в чат: не удаляйте местные изменения и не используйте принудительный сброс. GitHub хранит код; игру запускаем на своём компьютере. Размещение игры в интернете в этот процесс не входит.

## Как устроен проект

```text
index.html → src/main.ts → Phaser
                            ↓
  Boot → MainMenu → CharacterSelect → Room
             ↑          ↑              │
             └── Esc ───┴──── Esc ─────┘

Меню: src/ui + src/data/characters.ts + src/assets
Комната: RoomScene + Beetle + src/settings.ts

Клавиатура → движение игрока → столкновение со стенами
           → выстрел → движение снаряда → удаление у стены
```

- `src/main.ts` создаёт игру, подключает физику и сцену.
- `src/scenes/BootScene.ts` загружает фоны и создаёт временную текстуру персонажа.
- `src/scenes/MainMenuScene.ts` показывает согласованный фон и кнопки «Играть»/«Выход».
- `src/scenes/CharacterSelectScene.ts` показывает упрощённый лагерь, ячейки и отдельную заглушку друида на бревне.
- `src/ui/MenuButton.ts` отвечает за внешний вид, наведение и клики кнопок; `src/ui/layout.ts` — за координаты интерфейса; `src/ui/sceneHelpers.ts` — за общие операции сцен меню.
- `src/data/characters.ts` задаёт порядок и доступность персонажей. Пока доступны только данные друида, другие ячейки закрыты.
- `src/rendering/placeholderDruid.ts` рисует отдельную временную текстуру сидящего друида. Её можно заменить без изменения лесного фона.
- `src/assets/` содержит два самостоятельных фона меню.
- `src/scenes/RoomScene.ts` рисует комнату и персонажа, читает клавиши, управляет движением и снарядами, выбирает точку появления жука, обрабатывает попадания, HP друида, контактный урон и смерть.
- `src/entities/Beetle.ts` отвечает за преследование, здоровье и отображение жука.
- `src/settings.ts` содержит размеры комнаты, скорости персонажа, снаряда и врага, здоровье друида и врага, интервалы стрельбы и контактного урона.
- `src/style.css` оформляет страницу вокруг игры.

Phaser обновляет сцену каждый кадр. Скорости задаются в пикселях в секунду, поэтому движение не привязано к частоте кадров. Снаряды используются повторно вместо бесконечного создания новых объектов.

## Меню и визуальный стиль

Главное меню использует согласованную иллюстрацию леса с друидом у костра. Экран выбора сохраняет расположение костра и бревна, но использует более простые пиксельные формы. Персонаж-заглушка и все кнопки рисуются поверх фона отдельно: текст не встроен в изображения. Три ячейки расположены слева; первая доступна, остальные затемнены и не реагируют на выбор.

«Лесной лагерь» — заголовок сцены, не утверждённое название игры. Решения об образе героя и дальнейшей модульности записаны в [docs/VISUAL_STYLE.md](docs/VISUAL_STYLE.md). Сценам можно менять оформление независимо от физики и боя комнаты. Каждый новый вход в комнату начинает попытку с полным здоровьем.

Сборка использует относительные пути к ресурсам (`vite.config.ts`), чтобы не привязывать игру к корню веб-сервера. Это подготовка для будущей настольной упаковки; Electron и интеграция со Steam пока не добавлены.

## Первый враг и его поведение

Один лесной жук появляется в случайной точке внутри комнаты минимум в 240 пикселях от начальной позиции друида. Он движется со скоростью 90 пикселей в секунду, друид — 220. Три попадания уничтожают жука; каждое попадание расходует снаряд. Полоски над жуком показывают оставшееся здоровье, а после победы появляется сообщение. Нажмите R для новой попытки со случайным местом появления.

```text
Позиция друида − позиция жука
             ↓
   Направление к друиду
             ↓
Единичный вектор × скорость жука
             ↓
    Скорость физического тела
```

Жук пересчитывает направление каждый кадр, поэтому следует за новым положением игрока. Нормализация вектора оставляет скорость одинаковой при любой дистанции и направлении. Phaser применяет эту скорость с учётом прошедшего времени. Жук идёт до самого друида и наносит контактный урон. Персонажи не толкают друг друга, поэтому друид может уйти из контакта на WASD.

В комнате нет внутренних препятствий, поэтому прямого преследования достаточно. Если добавим непроходимые препятствия, понадобится отдельный поиск пути: сначала маршрут вокруг препятствий, затем движение к очередной точке маршрута.

## HP друида и контактная атака

Друид начинает с 3 HP. В правом верхнем углу показаны три сердца и счётчик `HP 3/3`. При настоящем пересечении физических тел жука и друида сразу снимается 1 HP, а друид кратко вспыхивает. Если контакт продолжается, следующий удар снимает ещё 1 HP через 1000 миллисекунд игрового времени. Таким образом, неподвижный друид теряет HP в моменты контакта, +1 секунда и +2 секунды.

Когда друид отходит или жук погибает, урон прекращается. Разрыв контакта сбрасывает его таймер: новое соприкосновение снова наносит мгновенный удар, даже если после предыдущего прошло меньше секунды. Время измеряется игровыми часами, а не количеством кадров. Урон проверяется только во время контакта, фонового таймера атаки нет.

При 0 HP движение, стрельба и физика останавливаются, появляется сообщение «Друид пал». Клавиша R запускает новую попытку с 3 HP и новым жуком, сбрасывает контактный таймер и возобновляет физику.

## Проверки

```bash
npm run build
npm test
```

Сборка сначала проверяет типы TypeScript, затем создаёт `dist/`. Команда `npm run preview` запускает собранную версию.

`npm test` самостоятельно запускает временный Vite на порту 4175 и проверяет игру в Chromium. Сначала проверяет стартовое меню, загрузку фонов, кнопки, закрытые ячейки, выбор, запуск комнаты, клавиатуру и повторные переходы. Затем выполняет проверки WASD, отпускания клавиш, диагонали, всех стен, стрельбы, повторного использования снарядов, боя и HP. Исходные проверки управления изолированы от врага. Проверки контактного урона охватывают HUD, мгновенный удар, секундные интервалы, уход, повторный контакт, смерть и восстановление после R. Требуется установленный Chromium. В облачной среде он расположен в `/usr/bin/chromium`; на другом компьютере задайте переменную `CHROMIUM_PATH` с путём к браузеру. Скриншоты сохраняются в `test-results/main-menu.png`, `test-results/character-select.png` и `test-results/room.png`. Сервер теста завершается автоматически.

## Направление игры

Ориентир — структура The Binding of Isaac: отдельные комнаты, процедурные забеги, враги, боссы, предметы и синергии. Герой — магический друид без превращений в животных. Цветение, сезоны и взаимодействие с растительным окружением — направления для дальнейшего обсуждения; их правила пока не утверждены. Eldruid — личный ник автора, не название игры.

Следующие задачи удобно ставить Codex через желаемое поведение, например: «Добавь одного врага, который медленно идёт к друиду и исчезает после трёх попаданий». Codex меняет проект и проверяет результат; принятые решения сохраняем в документации.
