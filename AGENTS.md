# Работа над druid-game

- Пользователь учится пользоваться Codex. Объясняйте изменения кратко на русском, через поведение игры и связи между частями проекта. Не утверждайте невыбранные игровые механики как требования; контекст находится в README.md.
- Текущий художественный фокус и отложенные пожелания сохранены в `docs/project-notes.md`. Мышей, количество деревьев и отложенные изменения движения не реализовывайте до возвращения пользователя к соответствующим задачам.
- Для случайно генерируемых объектов сообщайте диапазоны количества и основные правила размещения. Число уточняющих вопросов определяется задачей, без искусственного ограничения двумя-тремя. Если художественный запрос неоднозначен, сначала уточните его у пользователя и дождитесь ответа до реализации.
- Согласованный способ работы: Codex меняет код удалённо, отправляет проверенные завершённые этапы в `origin/main`, пользователь получает их на компьютере через `git pull --ff-only` и играет локально. Это постоянное разрешение на обычные коммиты и отправку изменений в этот репозиторий в рамках запрошенных задач. Если пользователь просит только обсуждение или обзор, ничего не меняйте и не отправляйте.
- Не размещайте игру на внешнем сайте и не переходите на интеграцию Codex с VS Code без запроса пользователя.
- Не выводите изображения, Canvas и веб-предпросмотры в чат: интерфейс пользователя показывает серые квадраты. Проверяйте визуальные изменения внутренними средствами без вывода картинок; сообщайте об обновлении GitHub и команде `git pull --ff-only`.
- При подключении явно выбранного PNG сохраняйте его рисунок: не заменяйте утверждённый вариант новой генерацией. Если эскиз содержит персонажа вместе с окружением, честно указывайте это; отделение слоёв не должно незаметно менять внешний вид.
- Готовые спрайты из выбранного изображения нарезайте механически, сохраняя исходные непрозрачные пиксели, цвета и форму. Не подменяйте отсутствующий исходный файл генерацией. Если доступна только картинка в переписке, запросите исходный PNG или ссылку на него и продолжайте независимые исправления.
- Перед изменениями проверяйте состояние рабочей папки и удалённой ветки. Сохраняйте чужие изменения. Перед отправкой проверяйте новые коммиты в `origin/main` и согласуйте с ними свою работу, не переписывая историю и не используя force push.
- Для изменений игрового поведения выполните `npm run build` и `npm test`; отдельно проверьте новый сценарий, если существующие тесты его не покрывают. Для изменений только документации повторная проверка игры не обязательна. Не заявляйте, что непроверенное поведение работает.
- Коммитьте исходники, документацию, тесты и lockfile. Не коммитьте `node_modules`, `dist`, `.npm-cache`, `test-results`, секреты или местные журналы.
- В конце сообщайте результат, проверки, отправленный коммит и действия пользователя для получения обновления. Если изменились зависимости, напомните выполнить `npm ci` и перезапустить сервер.
- Каждый итоговый ответ после работы с кодом также должен содержать ссылку загрузки референсов: `https://github.com/ElderDragonfly/druid-game/upload/main/docs/art` и напоминание нажать **Commit changes** после загрузки.
- Не меняйте редактор сущностей (интерфейс, карточки, описания, новые настройки) до отдельного распоряжения пользователя. Не включайте сопутствующие обновления редактора в игровые задачи автоматически.
- Облачная задача уже изолирована. Используйте существующий checkout; не создавайте Git worktree без явного запроса пользователя.

- Базовый баланс друида, волка и мыши хранится в `src/data/entities.json`; не дублируйте эти числа в игровых определениях. Локальный редактор `/editor.html` использует общую проверку `entitySchema.ts` и обновляет живой забег через dev-сервер. При изменениях редактора/схемы/применения данных выполняйте `npm run test:editor` дополнительно к обычным проверкам. Тесты игры используют утверждённый баланс `scripts/fixtures/entities-baseline.json`; изменения этого эталона должны быть намеренными, не копируйте туда автоматически пользовательские эксперименты.
