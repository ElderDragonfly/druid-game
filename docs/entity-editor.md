# Локальный редактор существ

Редактор находится в этом же проекте, открывается в браузере и меняет реальные игровые данные. Ничего публиковать в интернете не нужно. Новых зависимостей для него не добавлено.

## Запуск

В терминале в папке `druid-game`:

```bash
git pull --ff-only
npm run editor
```

Откроется браузер с редактором. Терминал оставьте работать. Если браузер не открылся, возьмите адрес Local, который напечатал Vite, и допишите `/editor.html`. Например, если Local заканчивается портом 5173, редактор находится по тому же адресу с `/editor.html`. Если порт занят, Vite выберет другой — используйте адрес именно из терминала.

Кнопка **«Открыть игру ↗»** сверху редактора открывает игру от того же сервера в соседней вкладке. Начните забег и переключайтесь между вкладками. Удобно разместить два окна браузера рядом.

Если у вас уже работает `npm run dev`, второй сервер не нужен: откройте `/editor.html` на адресе уже работающей игры. Важно использовать один адрес: например, в обеих вкладках `localhost`, либо в обеих `127.0.0.1`. Для записи редактору нужен локальный доступ с этого компьютера. `npm run editor` сразу использует локальный адрес.

Для остановки нажмите Ctrl+C в терминале. Позже повторите `npm run editor`: сохранённые параметры останутся. `npm ci` нужен при первой установке проекта или изменении зависимостей; этот этап новых зависимостей не добавляет.

## Что находится в редакторе

Слева три карточки: **Друид**, **Волк**, **Мышь**. Переключение карточки не теряет несохранённые значения других существ.

В центре — увеличенный просмотр принятых игровых спрайтов:

- друид: стойка, ходьба, каст и попадание, восемь ракурсов;
- волк: стойка, прогулка, погоня, два укуса и смерть, зеркальные боковые ракурсы;
- мышь: пробежка, подъём, осматривание и опускание, два боковых ракурса.

Выберите анимацию и направление. **«Пауза»** останавливает просмотр, **«Следующий кадр»** позволяет разобрать движение. В просмотре анимации повторяются для удобства изучения; в игре смерть и отдельные реакции проигрываются по своим правилам. Скорость просмотра ходьбы/бега и каста учитывает числа в форме. Просмотр не заменяет проверку движения в самой игре.

Ниже описано поведение существа. В **«Скрытых и технических свойствах»** показаны размеры коллизий и другие существующие правила. Эти сведения пока доступны для просмотра. Лут честно отмечен как не реализованный: таблиц выпадения в игре ещё нет.

Справа — редактируемые характеристики и параметры поведения с пояснениями и единицами. Свойства, требующие новой игровой механики, пока добавляются в коде. Редактор позволяет настраивать уже реализованное поведение.

## Изменение и сохранение

1. Выберите существо слева.
2. Измените нужные числа справа. Например, скорость погони волка `1` → `0.8`.
3. Вверху появится **«Есть несохранённые изменения»**. Пока это черновик: игра ещё не изменена.
4. Нажмите **«Сохранить в проект»**. Одна кнопка сохраняет изменения всех трёх карточек.
5. Дождитесь сообщения **«Сохранено в src/data/entities.json»**. Открытая игра получает новые данные без перезагрузки страницы и забега.
6. Вернитесь в игру и проверьте результат. Не требуется заново запускать сервер.

Некорректные значения блокируют сохранение и сопровождаются объяснением. Например, минимум количества не может быть больше максимума; момент попадания волка должен быть раньше окончания укуса; здоровье должно быть целым положительным числом. Пустое поле тоже нельзя сохранить.

**«Отменить несохранённое»** возвращает все карточки к последним загруженным значениям. Уже записанный файл эта кнопка не меняет.

**«Загрузить с диска»** перечитывает актуальный файл проекта. При наличии черновика редактор попросит подтвердить его отмену. Чтобы отменить уже сохранённую настройку, введите прежнее число и снова сохраните.

Если файл изменился из другой вкладки, чистая форма обновится автоматически. При несохранённом черновике редактор сохранит его на экране и заблокирует запись до загрузки актуальной версии: чужие изменения не будут незаметно затёрты. При необходимости предварительно запишите свои значения.

## Когда виден результат

| Настройка | Применение |
| --- | --- |
| Скорость друида, скорострельность, дальность | К живому друиду открытого забега. Дальность влияет на следующие желуди. |
| Максимум HP друида и волка | К живым существам, с сохранением числа потерянных HP. При уменьшении остаётся минимум 1 HP. Мёртвые не оживают. |
| Скорость волка и мыши | К уже существующим живым существам; кадры движения следуют за скоростью. |
| Урон | К следующим проверкам попадания, включая уже летящий жёлудь. |
| Скорость снаряда | К новым снарядам. Летящие сохраняют скорость и дальность, с которыми были созданы. |
| Обнаружение и досягаемость волка | К следующим проверкам. Уже замеченного друида волк не забывает при уменьшении радиуса. |
| Длительность укуса, момент попадания, время осматривания мыши | Текущий таймер не сбрасывается, меняется порог проверки/завершения. |
| Длина прогулок, паузы отдыха и восстановления | Следующие маршруты и паузы берут новое значение. Начатые таймеры завершаются своим ходом. |
| Минимум/максимум количества существ | При новой генерации. Нажмите **R** в игре или начните новый забег. |

Открытый забег продолжает жить: позиции, лес, состояние боя и трупы сохраняются. Изменение скорости/скорострельности/дальности базовых данных сохраняет относительные модификаторы текущего персонажа.

**«Продолжить» загружает характеристики, сохранённые внутри забега.** Поэтому для проверки именно новых стартовых значений начните новый забег или нажмите R. Иначе старый сейв может выглядеть как «настройка не применилась». Сейв забега и файл баланса — разные вещи.

Карточка выбора друида показывает актуальное стартовое HP при следующем входе на экран выбора.

## Единицы и пример

- Скорость `1` = **146⅔ игровых единиц в секунду**, наша общая базовая скорость. Скорость волка `0.8` — 80% этой величины. Изменение текущей скорости друида не меняет единицу измерения волка.
- У мыши скорость указана непосредственно в **единицах/с**: исходно `90`.
- Скорострельность `1` = каст за **1005 мс**. При `2` он длится вдвое меньше. Выпуск — на 75% жеста.
- Дальность `1` = овал с полуосями **384 по горизонтали и 216 по вертикали**. При `0.5` — 192 и 108.
- Время указано в миллисекундах: `1000 мс = 1 с`.
- Генерация выбирает случайное число в диапазоне включительно **на всю локацию**. Исходно волков **0–18**, мышей **0–9**; без квот отдельных экранов. При недостатке свободных мест может появиться меньше выбранного количества.

Для первой проверки: откройте волка, поставьте скорость погони `0.8`, урон `0`, сохраните. Он станет медленнее, а укусы перестанут отнимать HP. После эксперимента верните скорость `1` и урон `1`, сохраните снова.

## Где хранится результат и как передать его в GitHub

Эта памятка также доступна прямо в редакторе, внизу справки: «Как сделать коммит и отправить настройки в GitHub».

[Полная пошаговая инструкция по Git: открытие терминала, просмотр изменений, add, commit, push и проверка результата](git-workflow.md).

**«Сохранить в проект» записывает файл на вашем компьютере:**

```text
src/data/entities.json
```

Изменения переживают закрытие браузера и перезапуск компьютера. Это общие стартовые данные игры, не localStorage и не отдельный сейв персонажа. Следующая `npm run build` включает их в сборку игры.

Сохранение в редакторе **не делает Git-коммит и не отправляет данные на GitHub**. Чтобы я видел ваши изменения при следующей работе, отправьте их в репозиторий. Во втором терминале в папке проекта:

```bash
git status
git diff -- src/data/entities.json
git add src/data/entities.json
git commit -m "Tune creature balance"
git push origin main
```

`git diff` показывает, какие числа изменились; `git add` выбирает файл для коммита; `git commit` сохраняет версию в локальной истории; `git push` передаёт её на GitHub. Затем сообщите в чате, что отправили баланс, и я проверю обновлённую ветку перед изменениями.

Если `git pull --ff-only` или `git push` откажется работать из-за местных изменений/новых удалённых коммитов, пришлите текст ошибки. Не делайте force push и не сбрасывайте файл с вашими настройками. Лучше отправлять свои изменения до следующего моего этапа работы.

## Как это связано с игрой

```text
Форма редактора → проверка → локальный сервер Vite → entities.json
                                                       │
                                      уведомление открытым вкладкам
                                                       ↓
                                      общие данные → живые существа
```

- `src/data/entitySchema.ts` описывает поля, диапазоны и проверку; её используют форма, сервер и игра.
- `src/data/entities.json` — единственный редактируемый источник баланса.
- `src/data/entityBalance.ts` хранит текущие данные и уведомляет подписчиков об изменениях.
- `src/data/characters.ts`, `wolf.ts`, `mouse.ts`, `acorn.ts` связывают числа с игровыми определениями. Рисунки и размеры тел остаются отдельно.
- `RoomScene` применяет обновление к живым существам и снимает подписку при выходе.
- `src/editor/` — интерфейс и просмотр исходных анимаций.
- `tools/entityEditorPlugin.ts` — чтение/сохранение фиксированного файла при разработке. Проверяет локальный адрес, схему и версию файла; записывает через временный файл и замену. В сборке игры этого обработчика нет.

Это локальный инструмент разработки. В публичной/установочной версии игры редактор не появляется и файлового доступа к проекту не получает.

## Проверки для разработки

```bash
npm run build
npm test
npm run test:editor
```

Игровые проверки используют утверждённый исходный баланс из `scripts/fixtures/entities-baseline.json`, чтобы ваши эксперименты со скоростью и HP не ломали проверку старых сценариев. Тест редактора пишет в отдельный временный JSON и не меняет ваш файл.

Последняя команда проверяет реальное сохранение, уведомление игры, просмотр анимаций, отмену черновика, конфликты и отказ на неверные данные. Для браузерных проверок нужен Chromium (как и для существующего `npm test`); редактору для обычной работы он отдельно не нужен.
