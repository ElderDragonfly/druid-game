# Basic 04 — игровые циклы ходьбы

Образ основан на утверждённом [Druid 04 Basic](../druid-sprites-v1/druid-04-basic.png): верёвочный пояс, голая кривая ветка-посох, без растений, медальона и подвесок. Подробный PNG Basic подключён только к маленькой доступной карточке «Друид» на экране выбора. Фон лагеря и сидящая фигура сохранены.

Все четыре цикла подключены к игре вместе с [неподвижными позами](idle-64x80.png). Неподвижный атлас собран из проходной фазы каждого направления, поэтому внешность при остановке не меняется. Маленькая карточка выбора использует исходный подробный Basic; фон и сидящий друид не менялись.

Во всех GIF четыре кадра по 240 мс, цикл 960 мс. Предпросмотр увеличен ×4 ближайшим соседом, размер 256×320. В игре анимация задана по 160 мс при опорной скорости 220; индивидуальный `timeScale` связывает темп с движением. Стартовая скорость 220 × 2/3 даёт те же 240 мс/кадр. Модификаторы скорости сохраняют текущую фазу, остановка возвращает неподвижную позу.

Прозрачные полосы кадров, каждая 256×80: [вниз](walk-down-64x80.png), [вверх](walk-up-64x80.png), [влево](walk-left-64x80.png), [вправо](walk-right-64x80.png). Каждый кадр — настоящая сетка 64×80, опора на строке 75, прозрачность 0/255. GIF ограничены общей палитрой в 256 цветов для каждого направления, без отдельной палитры на кадр и без дизеринга.

## Как сохраняется рисунок и движение

Верх и низ используют прежние принятые полосы. Из нового [листа локальных исправлений](front-back-edits-source.png) взяты только области пояса и верхушки посоха. Вне прямоугольников `localPatches` в [animations.json](animations.json) исходные пиксели сначала копируются без изменения. Затем программно согласуется палитра зелёной ткани и коричневых ног с Basic; положение ног, рук, головы и рисунок движения вне областей исправлений сохраняются. Со спины пояс закрыт плащом и поверх него не дорисовывается.

Боковые позы нарисованы заново по схемам короткого шага: контакт → проходящая нога → противоположный контакт → проходящая нога. Отдельно согласована светотень ближней и дальней ноги, чтобы смена опоры читалась. Вправо горизонтальный размах ног сокращён на 25% с плавным переходом от неизменённого таза. Свободная согнутая рука взята из одной позы и поворачивается целиком вокруг плеча на −12°, 24°, 62°, 24°: в передней фазе кисть немного выходит вперёд корпуса. Старая кисть удалена, включая смещённый светлый фрагмент. Форма и толщина руки сохраняются. Исходные листы: [влево](left-source.png), [вправо](right-source.png). PNG после подготовки включает эти исправления; он не является простым уменьшением исходного листа.

У боковых направлений **рука с посохом вынесена в отдельный слой**. В каждом направлении используется одна исходная форма, которая целиком поворачивается на 0/±4° и смещается по вертикали на 0–2 пикселя. Посох не укорачивается при переносе, хват не перерисовывается на каждой фазе. На растровой сетке контур при повороте меняется из-за округления пикселей. Положение посоха перед ногами при виде влево и за телом при виде вправо сохранено. Слева край плаща дополнительно перекрывает начало рукава.

Слои левого направления: [тело](walk-left-body-64x80.png), [рука и посох](walk-left-arm-staff-64x80.png), [край плаща поверх плеча](walk-left-cloak-foreground-64x80.png). Перед телом в порядке сборки идёт [дальняя кисть](walk-left-far-hand-64x80.png): видны только 1–2 пикселя у края одежды в части цикла, предплечье скрыто. Затем тело → рука с посохом → край плаща.

Слои правого направления: [рука и посох](walk-right-arm-staff-64x80.png), затем [тело](walk-right-body-64x80.png). [Свободная рука](walk-right-free-arm-64x80.png) сохранена отдельно для дальнейшей работы и уже включена в слой тела; повторно накладывать её не требуется.

Это начало подготовки сменных частей, а не готовая система экипировки: пояс пока входит в рисунок тела. Сам подробный Basic и прежние наборы сохранены в архивных папках без изменений. Игровые текстуры используют новые PNG напрямую, без дополнительной перекраски сапог.

## Повторная подготовка

`python scripts/prepare-basic-druid-walk.py` (Python 3 + Pillow, NumPy, SciPy). Использует сохранённые листы и существующие игровые полосы. Результат воспроизводим: повторный запуск не усиливает цветокоррекцию. Скрипт очищает отделённые фоновые артефакты новых рисунков, нормализует сетку, собирает локальные исправления, переносит палитру и формирует GIF. Для прозрачных пикселей выходных PNG RGB обнулён.

Проверены четыре уникальных кадра каждого GIF, длительности, прозрачность, границы фигур и точная пересборка боковых PNG из слоёв. В верхнем и нижнем направлениях альфа-канал вне областей локальных исправлений совпадает с принятым движением. Карточка проверяется в браузере: использует исходные пиксели утверждённого Basic и прежний размер 94 по высоте. `npm test` проверяет совпадение игровых текстур с PNG, полный цикл каждого направления, остановку, изменение скорости, столкновения и повторные входы в комнату.
