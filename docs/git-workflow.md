# Как сохранить свои изменения в GitHub

Редактор и Git делают разные вещи:

```text
«Сохранить в проект» → файл на вашем компьютере
          git add   → выбрать изменения для коммита
       git commit   → записать версию в локальную историю
         git push   → отправить коммит на GitHub
```

Пока выполнено только сохранение в редакторе, я не вижу ваши новые значения в облачной копии проекта. После успешного push они появятся в GitHub, и я смогу учитывать их в следующей работе.

## 1. Откройте терминал в папке игры

Терминал, где работает `npm run editor` или `npm run dev`, оставьте работать. Для Git откройте **второй терминал**.

В Windows: откройте папку `druid-game` в Проводнике, нажмите правой кнопкой по пустому месту и выберите «Открыть в Терминале». Если терминал уже открыт в другой папке, перейдите в проект командой `cd` с вашим путём, например:

```powershell
cd "C:\Games\druid-game"
```

Это пример пути: замените его на место, где у вас скачан проект. Кавычки нужны, если в пути есть пробелы. В папке проекта находятся `package.json`, `src`, `docs`.

## 2. Сначала сохраните значения в редакторе

Измените нужные числа и нажмите **«Сохранить в проект»**. Дождитесь сообщения о сохранении. В этом случае изменяется `src/data/entities.json`.

Затем во втором терминале выполните:

```bash
git status
```

Ожидаемая ветка — `main`. Среди изменённых файлов будет:

```text
modified: src/data/entities.json
```

Если написано `nothing to commit, working tree clean`, Git не видит новых изменений: возможно, значения уже были сохранены коммитом или вы вернули прежние числа. Если ошибка `not a git repository`, терминал открыт не в папке проекта.

## 3. Посмотрите, что изменилось

```bash
git diff -- src/data/entities.json
```

Строки с `-` показывают старые значения, с `+` — новые. Например, скорость волка `1` меняется на `0.8`. После первого сохранения может измениться и форматирование JSON — появиться больше переносов строк. Это не дополнительное изменение игровой механики.

Если открылся длинный просмотрщик, клавиши вверх/вниз прокручивают его, **Q** закрывает просмотр.

## 4. Выберите файл для коммита

```bash
git add src/data/entities.json
git status
```

Файл переместится в раздел `Changes to be committed`. Это означает, что он подготовлен для коммита, но ещё не отправлен на GitHub.

При желании посмотрите подготовленный результат:

```bash
git diff --cached -- src/data/entities.json
```

Если вы после `git add` ещё раз изменили числа и сохранили их в редакторе, повторите `git add src/data/entities.json`, чтобы в коммит попала последняя версия.

## 5. Создайте коммит

```bash
git commit -m "Tune creature balance"
```

Текст в кавычках — ваше краткое описание, например `Slow wolves and increase druid range`. Коммит запишет выбранные изменения в историю на вашем компьютере. Git напечатает короткий идентификатор версии.

Если Git впервые просит указать автора (`Author identity unknown`), задайте имя и email **для этого репозитория**, затем повторите commit:

```bash
git config user.name "Ваше имя"
git config user.email "Ваш email из настроек GitHub"
```

Вместо пояснений в кавычках подставьте свои значения. В GitHub email можно посмотреть в Settings → Emails; там же доступен адрес `noreply`, если вы используете его для коммитов.

## 6. Отправьте коммит

```bash
git push origin main
```

`origin` — ваш репозиторий GitHub, `main` — ветка, с которой мы работаем. При необходимости Git предложит войти в GitHub, обычно через браузер.

После успешной отправки появится строка вида:

```text
старый_коммит..новый_коммит  main -> main
```

## 7. Убедитесь, что коммит дошёл

```bash
git log -1 --oneline
git status
```

Первая команда показывает последний локальный коммит, вторая — оставшиеся местные изменения. Откройте [историю main на GitHub](https://github.com/ElderDragonfly/druid-game/commits/main/) и найдите то же сообщение/идентификатор коммита. Это подтверждает, что он есть на GitHub.

Теперь можно написать мне: «Я отправил новые характеристики, проверь main».

## Наш обычный порядок работы

1. Перед новыми местными экспериментами получите моё последнее обновление через `git pull --ff-only`.
2. Настройте числа в редакторе, проверьте игру, нажмите «Сохранить в проект».
3. Сделайте add → commit → push по шагам выше.
4. Сообщите мне об отправке до следующего этапа изменений кода.

Если pull или push отклонён из-за новых удалённых коммитов или местных изменений, сохраните текст ошибки и пришлите в чат. Мы согласуем версии, сохранив ваши настройки. Коммит на компьютере остаётся в истории и после неудачного push.

## Короткая памятка после знакомства с шагами

Все команды вводятся в папке `druid-game` после сохранения в редакторе:

```bash
git status
git diff -- src/data/entities.json
git add src/data/entities.json
git commit -m "Tune creature balance"
git push origin main
git status
```
